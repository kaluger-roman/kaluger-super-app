## Аргументы

$ARGUMENTS

## Что сделать

Шкала и формат — `docs/issue-priority.md`, прочитай его целиком. Оценку выбирает Haiku-субагент, записывает её только `scripts/issue-priority.mjs set` (блок в описании руками не править).

### 1. Собрать issues

- Номера в аргументах → для каждого `gh issue view <N> --json number,title,body,labels,state`; закрытые пропустить.
- Без номеров → `node scripts/issue-priority.mjs unscored`.
- `--all` → `gh issue list --state open --limit 300 --json number,title,body,labels`.

Если список пуст — сказать «все открытые issues уже оценены» и закончить.

### 2. Оценить (Haiku)

Разбить на пачки по 8 issues и запустить по субагенту на пачку, все в одном сообщении (параллельно): `Agent` с `model: "haiku"`, `subagent_type: "general-purpose"`. Субагенту ничего не нужно искать в коде и в GitHub: всё нужное — в промпте. Промпт:

- полный текст `docs/issue-priority.md` (разделы Context, Criteria, Bands);
- для каждого issue: номер, заголовок, метки, тело (без старого блока `<!-- priority -->…<!-- /priority -->`, если он есть; тело длиннее ~4000 символов — обрезать);
- задача: по каждому issue выбрать баллы по четырём критериям строго по таблицам, учитывая, что прод — небольшая база реальных пользователей, а инфраструктура разработки нужна агентам каждый день; объяснение — одна фраза на русском, почему именно столько (что ломается, у кого, есть ли обход);
- формат ответа — только JSON-массив без пояснений: `[{"number": 12, "impact": 30, "reach": 15, "urgency": 10, "workaround": 8, "why": "…"}]`.

Проверить ответ: JSON парсится, есть каждый номер пачки, баллы — целые в пределах (40/25/20/15), `why` не пустой. Пачку с ошибкой перезапустить один раз; если снова не так — эти issues перечислить в итоге как неоценённые.

### 3. Записать

По каждому issue:

```bash
node scripts/issue-priority.mjs set <N> --impact <i> --reach <r> --urgency <u> --workaround <w> --why "<why>"
```

### 4. Итог

Таблица, отсортированная по оценке: `#N` (ссылка), оценка, метка, заголовок, «почему». Отдельной строкой — неоценённые, если есть. Ничего больше не делать: issues не чинить и не закрывать.
