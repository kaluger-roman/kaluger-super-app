# Работа с Codex

Основные инструкции находятся в `AGENTS.md`, уточнения — в пакетах. Этот документ
читается по необходимости. Конвенции и спеки сохраняют знания о приложении.
Модель наследуется из настроек Codex. Сценарии с сабагентами сохранены, включая
девять независимых направлений review; см. [протокол делегирования](subagents.md).
Навыки комплексной разработки задают
верхнюю границу повторных проверок, а заканчивают их раньше, когда результат проверен.
Повторяемые процедуры сохранены в `.agents/skills/`: [каталог навыков](skills.md).

## Обычная задача

1. Проверить текущий checkout, ветку и diff; прочитать нужные конвенции и код.
2. Для небольшого исправления воспроизвести проблему и внести минимальную правку.
   Для большой функции уточнить требования и вести `spec.md`, `plan.md`, `tasks.md`
   в соответствующем `specs/<id>-<name>/`. Добавлять контракты/исследование, только
   когда они помогают реализации. Фиксировать решения и результаты проверок.
3. Реализовать поведение с тестами. Не смешивать посторонние находки с задачей.
4. Запустить относящиеся к изменению проверки и просмотреть итоговый diff.
5. Для UI проверить изменённый сценарий в браузере. Для auth, финансов, миграций,
   realtime и видеозвонков проверить ошибки и границы доступа/состояния.
6. Сообщить результат, проверки и ограничения. Коммит/push/PR — в рамках запроса
   пользователя. Мерж и деплой не следуют автоматически из завершения разработки.

Утверждение нового UX нужно, когда без выбора пользователя нельзя определить
поведение; не останавливать каждую техническую итерацию ради формального checkpoint.

## Спецификации

Старые папки `specs/` и шаблоны `.specify/templates/` сохранены. Можно попросить
создать спецификацию обычным текстом или вызвать `$speckit-specify`; для остальных
этапов есть `$speckit-clarify`, `$speckit-plan`, `$speckit-tasks`, `$speckit-implement`
и другие навыки из каталога.
При работе скриптов со старой спецификацией явно задавайте имя:

```bash
SPECIFY_FEATURE=039-call-fullscreen bash .specify/scripts/bash/check-prerequisites.sh --json
```

Это работает и для `codex/...`, и для detached HEAD. Точное имя важно: в истории есть
несколько функций с одинаковым числовым префиксом. Генерация `AGENTS.md` из истории
планов удалена: инструкции поддерживаются вручную и остаются короткими.

## Review и поиск проблем

Просматривать изменение против выбранной базы вместе с незакоммиченными файлами.
Проверять реальные цепочки вызовов и существующие тесты, а не только отдельные строки.
В отчёт включать воспроизводимые дефекты с файлом/строкой, условиями и последствиями;
отделять подтверждённый дефект от предположения. Не выдавать вкусовые правки за баги.
После исправления повторять затронутые проверки; новые круги нужны при новых находках.

Для bug/improvement hunt сначала определить область и критерий завершения.
Проверять дубликаты по существующим отчётам/issues. По умолчанию находки возвращаются
в чате; длительный аудит можно сохранить в существующей папке отчётов. Явные вызовы
`$bug-hunt` и `$improve-hunt` сохраняют прежний режим создания подтверждённых issues;
`--report` оставляет только локальный отчёт. Для одного issue есть `$create-issue`,
для оценки — `$score-issues`. Дубли и приоритет проверяются по `docs/issue-priority.md`.

## QA и E2E

- Для повседневной разработки — [dev-stack](dev-stack.md).
- Для ручной проверки production-сборки — [qa-stack](qa-docker.md).
- Проверять пользовательские сценарии, негативные пути, загрузку/пустые состояния,
  обновление страницы и два пользователя там, где это влияет на поведение.
- Для QA-отчёта записывать commit/ветку, URL, шаги, ожидаемый/фактический результат,
  доказательства и непроверенное. Скриншоты хранить локально в ignored `screenshots/`.
- E2E-аудит: сопоставлять изменённые user journeys с существующими тестами, отмечать
  непокрытые и затронутые сценарии. Следовать `docs/conventions/e2e-testing.md`.
- Лимит QA задавать областью, сценариями или временем. Старый процент пятичасового
  лимита Claude не является измеримым бюджетом Codex.

## Changelog, новости и PR

Обновлять `CHANGELOG.md` по фактическому diff/истории, сохраняя старые записи.
Группы: Added, Changed, Fixed, Removed, Security, Infrastructure; английский текст, без
выдуманных хешей. Для текущих незакоммиченных изменений хеш не указывать.

Пользовательские новости — только для изменений продукта, на русском, без
инфраструктурных деталей. `npm --prefix backend run news:generate -- ...` создаёт
JSON; `news:sync` пишет в БД и не нужен для подготовки PR. Выпуск новостей и прод
выполняются отдельной явно заказанной задачей. `$changelog` обновляет историю,
`$news` готовит локальный JSON без записи в БД.

Для запрошенного PR: именованная ветка `codex/...`, проверки, осмысленный коммит,
push этой ветки, `gh pr create --draft --body-file <file>` либо обновление существующего
PR. Проверить CI. `Closes #N` — только для полностью решённых issues. Нет зависимости
от приватных транскриптов, session env или локального пути к чату.

## Что заменено при миграции

| Прежний механизм | Текущий процесс |
| --- | --- |
| `CLAUDE.md`, Copilot-дубли | `AGENTS.md` + инструкции пакетов |
| Все 25 `.claude/commands` | 25 соответствующих навыков в `.agents/skills/`; дополнительно `create-issue` |
| `/auto-feature`, `/auto-bug-fix` | `$auto-feature`, `$auto-bug-fix`: текущий worktree, сохраняемый прогресс, проверки по области задачи |
| `/speckit.*` | `$speckit-*`: те же этапы и артефакты, локальная среда Mac |
| 9 reviewer-агентов, Haiku/Sonnet scoring | 9 независимых reviewer-задач и отдельные scorer'ы Codex, параллельно в пределах слотов |
| Claude hooks на PR и пустой стартовый коммит | Git pre-commit, явные проверки, обычный `gh` |
| `repo-git.sh`, SSH/sshfs | Локальный `git` |
| VS Code Claude agents panel | Чаты и worktree в Codex |
| `qa-budget.mjs`, statusline dump | Ограниченная область/время QA |
| Общие `node_modules`, PostgreSQL на `home` | Свои зависимости, Docker БД на Mac |

Claude-команд/инструментов доступны в Git-истории до этой миграции. Исторические
спецификации, отчёты, конвенции и ops-скрипты сохранены.
