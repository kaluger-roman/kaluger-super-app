## 1. Добавление ученика с пустым именем: кнопка «Добавить» молча не срабатывает, без подсказки

- **Impact:** High
- **Effort:** S (≤2 ч)
- **Категория:** Visible Bug / UX
- **Где:** `URL: /students` → диалог «Добавить студента»
- **Скриншот:** `screenshots/2026-05-31-004-empty-submit-no-validation.png` (для контекста — пустая форма: `screenshots/2026-05-31-003-add-student-dialog.png`)

### Что увидел

1. На `/students` открыл «Добавить ученика».
2. Не заполняя ничего, нажал «Добавить».
3. Диалог остался открытым, поле «Имя студента \*» — без какой-либо красной подсветки или текста ошибки, кнопка «Добавить» по-прежнему зелёная и активная.
4. Внешне — **ровным счётом ничего не произошло**. При этом в консоли в момент клика вылетела ошибка: `Error: event: unit call from pure function is not supported, use operators like sample instead` (в `handleSubmit`).
5. Для сравнения: с заполненным именем сабмит проходит нормально (`POST /api/students → 201`), так что путь «happy path» рабочий — ломается именно ветка валидации.

### Почему это проблема

Учитель нажимает «Добавить», видит, что окно не закрылось и ничего не сообщили, — и думает, что «кнопка не работает» / «приложение зависло». Самая частая реакция — кликать ещё раз. Нет ни намёка, что причина — пустое обязательное поле «Имя». Для главной формы раздела это ощущается как поломка.

### Что предложить

- Показывать инлайн-ошибку под полем «Имя студента» (`Укажите имя ученика`) и подсвечивать поле красным при попытке сабмита.
- Либо держать «Добавить» задизейбленной, пока имя пустое, с подсказкой (`title`/текст), что именно нужно заполнить.
- Параллельно починить обработчик сабмита, чтобы он не падал с ошибкой Effector (`unit call from pure function`) — сейчас именно это, судя по всему, и прерывает показ валидации.

### Воспроизведение

```
1. Логин под qa-roam@test.local (роль «Преподаватель»)
2. /students → FAB «Добавить ученика»
3. Ничего не заполнять → нажать «Добавить»
4. (Наблюдение) Окно не закрывается, ошибки/подсказки нет, в консоли — JS Error в handleSubmit
```

## 2. После создания ученика нет явного подтверждения, а новая карточка «уезжает» вниз

- **Impact:** Medium
- **Effort:** S (≤2 ч)
- **Категория:** UX
- **Где:** `URL: /students` → после сохранения нового ученика
- **Скриншот:** `screenshots/2026-05-31-005-after-create-emoji-student.png`

### Что увидел

1. Создал ученика с именем «qa-roam Эмодзи 👨‍👩‍👧 Тест» (класс не указывал).
2. Диалог закрылся, список обновился сам (без F5) — это хорошо.
3. Но **никакого «Ученик добавлен» / тоста не появилось**, а сама новая карточка попала в группу «Без класса» в самом низу списка — на планшете после закрытия диалога на экране остаётся прежний верх («7 класс», «9 класс»), и нового ученика не видно без прокрутки.

### Почему это проблема

После сохранения возникает секунда неуверенности: «сохранилось ли?». Закрытие окна — это лишь косвенный сигнал; явного подтверждения нет, а результат не попадает в поле зрения. Пользователь может полезть создавать заново или решит, что не сработало.

### Что предложить

- Показывать короткий snackbar `Ученик добавлен` (2–3 с) после успешного `201`.
- Желательно проскроллить/подсветить только что созданную карточку (или раскрыть её группу), чтобы результат был виден сразу.

### Воспроизведение

```
1. /students → «Добавить ученика»
2. Заполнить только имя, класс не указывать → «Добавить»
3. (Наблюдение) Тоста нет; новый ученик — внизу в группе «Без класса», вне видимой области на планшете
```

## 3. Кабинет ученика → «Настройки»: настраивать по сути нечего; у ученика нет самостоятельной смены пароля

- **Impact:** Low
- **Effort:** M (полдня)
- **Категория:** UX / Copy
- **Где:** `URL: /student/cabinet/settings` (роль «ученик»)
- **Скриншот:** `screenshots/2026-05-31-007-student-settings.png`

### Что увидел

1. Зашёл в кабинет ученика, открыл раздел «Настройки».
2. Внутри — только два блока «только для чтения»: «Ваши данные» (ФИО, email с бейджем «Подтверждён») и «Преподаватель». Плюс приписка «Для изменения данных обратитесь к преподавателю.».
3. **Ни одной настройки, которую можно изменить:** ни пароля, ни уведомлений/напоминаний, ни часового пояса. При этом на этой же странице висит PWA-баннер, обещающий «push-уведомления», — но управлять ими негде.
4. На странице входа ученика тоже нет ссылки «Забыли пароль?» (есть только у преподавателя), а в самих настройках пароль не меняется — то есть у ученика **вообще нет способа сменить/восстановить пароль** самому.

### Почему это проблема

Раздел называется «Настройки», но ничего настроить нельзя — это обманывает ожидание (ученик заходит «поменять пароль/уведомления» и упирается в просмотр). Полная зависимость от преподавателя по любому изменению, включая пароль, — неудобно и для ученика, и для учителя (лишние обращения).

### Что предложить

- Либо переименовать раздел в «Профиль» / «Мои данные» (если изменять действительно нечего), либо добавить хотя бы смену пароля.
- Дать ученику самостоятельную смену пароля в «Настройках» и/или ссылку «Забыли пароль?» на форме входа ученика.

### Воспроизведение

```
1. Войти как ученик (вкладка «Ученик» на /login)
2. /student/cabinet/settings
3. (Наблюдение) Только просмотр данных; изменить/сменить пароль нельзя; на /login для ученика нет «Забыли пароль?»
```

## 4. Одна и та же сущность называется то «учеником», то «студентом»

- **Impact:** Low
- **Effort:** S (≤2 ч)
- **Категория:** Copy
- **Где:** `URL: /students` → диалоги «Добавить/Редактировать студента»
- **Скриншот:** `screenshots/2026-05-31-003-add-student-dialog.png`

### Что увидел

- Заголовок раздела и кнопки: «👥 Ученики», «Добавить ученика», группы «7 класс (1 **ученик**)», диалог удаления «Удалить **ученика**».
- А диалоги добавления/редактирования: «Добавить **студента**», «Редактировать **студента**», поля «Имя **студента**», плейсхолдер «Дополнительная информация о **студенте**».

### Почему это проблема

Разнобой в терминах делает интерфейс неаккуратным и на доли секунды сбивает: «студент» и «ученик» — это одно и то же или нет? Для продукта про репетиторство это заметная мелочь.

### Что предложить

- Привести к одному термину (судя по преобладанию — «ученик»): «Добавить ученика», «Имя ученика», «Информация об ученике» и т.д.

### Воспроизведение

```
1. /students → заголовок «Ученики», кнопка «Добавить ученика»
2. Нажать «Добавить ученика» → в открывшемся окне заголовок «Добавить студента», поле «Имя студента»
3. (Наблюдение) В одном потоке — два разных слова для одной сущности
```
