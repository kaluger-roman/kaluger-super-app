## 1. Регистрация нового учителя и подтверждение email

- **Приоритет:** Critical
- **Статус:** uncovered
- **Тег:** `@auth`
- **Существующие тесты по области:** нет

### Шаги journey

1. Учитель открывает `/register`, заполняет имя, email и пароль, нажимает «Зарегистрироваться».
2. `POST /api/auth/register` создаёт пользователя с `isEmailVerified: false`, отправляет письмо с 6-значным кодом.
3. Effector переводит на `/verify-email`.
4. Учитель вводит код в форме `EmailVerificationForm`.
5. `POST /api/auth/verify-email` ставит `isEmailVerified: true`, возвращает JWT.
6. Токен сохраняется в `localStorage`, редирект на `/`.

### Задействованные модули

- Frontend: `features/auth/ui/RegisterForm/RegisterForm.tsx`, `features/auth/models/register-form.model.ts`, `features/emailVerification/EmailVerificationForm/EmailVerificationForm.tsx`, `entities/verification/`
- Backend: `controllers/auth.ts` (`register`), `controllers/emailVerification.ts` (`verifyEmail`), `services/email.ts` (`POST /api/auth/register`, `POST /api/auth/verify-email`)

### Наблюдаемый результат

Учитель авторизован, попадает на дашборд, токен в `localStorage`.

### Почему критичен

Без регистрации учитель не может получить доступ к приложению — нулевая точка входа.

## 3. Восстановление пароля через email (forgot → reset)

- **Приоритет:** Critical
- **Статус:** uncovered
- **Тег:** `@auth`
- **Существующие тесты по области:** нет

### Шаги journey

1. Учитель на `/login` нажимает «Забыли пароль?», попадает на `/forgot-password`.
2. Вводит email → `POST /api/auth/forgot-password`. Бэк создаёт `PasswordResetToken` (SHA-256 хэш), отправляет письмо со ссылкой.
3. Учитель переходит по ссылке `/reset-password?token=...`.
4. `POST /api/auth/reset-password/verify` валидирует токен, форма открывается.
5. Вводит новый пароль и подтверждение → `POST /api/auth/reset-password`.
6. Бэк помечает токен `usedAt`, обновляет хэш пароля. Появляется «Пароль успешно изменён» и кнопка «Войти».

### Задействованные модули

- Frontend: `pages/forgotPassword/ForgotPasswordPage.tsx`, `features/forgotPassword/`, `pages/resetPassword/ResetPasswordPage.tsx`, `features/resetPassword/`
- Backend: `controllers/passwordReset.ts`, `services/passwordReset.ts`, `services/email.ts` (`POST /api/auth/forgot-password`, `/reset-password/verify`, `/reset-password`)

### Наблюдаемый результат

Новый пароль в БД, токен помечен использованным, можно войти с новым паролем.

### Почему критичен

Единственный способ восстановить доступ при утере пароля. Свежая фича (028-forgot-password) — повышенный риск регрессии.

## 8. Отмена оплаченного урока с автоматическим переносом оплаты

- **Приоритет:** Critical
- **Статус:** uncovered
- **Тег:** `@lessons`

### Шаги journey

1. В `LessonViewDialog` нажимает «Отменить» — параллельно `GET /api/lessons/:id/cancellation-info`.
2. Бэк: если `isPaid && paymentDate`, ищет ближайший будущий неоплаченный урок того же ученика с той же ценой.
3. Фронт показывает «Оплата NN ₽ от [дата] будет перенесена на следующий урок [дата/время]».
4. Учитель подтверждает → `PUT /api/lessons/:id` со `status=CANCELLED`.
5. Бэк в одной транзакции: `isPaid=false, paymentDate=null` на отменяемом + `isPaid=true, paymentDate=<old>` на следующем.
6. WS-broadcast, список перезагружается.

### Задействованные модули

- Frontend: `features/lessons/ui/LessonViewDialog/LessonDialogActions/`, `features/lessons/models/lesson-cancellation.model.ts`, `features/lessons/models/lessons-confirm-dialog.model.ts`
- Backend: `controllers/lessons/getCancellationInfo.ts` (`GET /api/lessons/:id/cancellation-info`), `controllers/lessons/updateLesson.ts` (`PUT /api/lessons/:id` — транзакция)

### Наблюдаемый результат

Отменённый урок без оплаты, следующий — с датой оплаты от отменённого; деньги не теряются.

### Почему критичен

Защищает финансовый учёт при отмене; ошибка — деньги исчезают/дублируются в системе.

## 9. Создание серии recurring уроков с автопродлением

- **Приоритет:** High
- **Статус:** uncovered
- **Тег:** `@lessons`

### Шаги journey

1. В `LessonForm` чекбокс «Регулярный урок» (`isRecurring: true`), время и день недели.
2. `POST /api/lessons`: бэк генерирует слоты с шагом 7 дней на 3 месяца, проверяет конфликты, создаёт `createManyAndReturn`, планирует push.
3. Ежедневно в 02:00 cron `processRecurringLessons` группирует существующие уроки по `tutorId-studentId-weekday-hour-minute`, продлевает серию до горизонта 3 месяца.
4. При смене времени одного урока серии: `previewShiftFutureRecurringLessons` → диалог подтверждения → `applyShiftFutureRecurringLessons` каскадно сдвигает все будущие уроки. Напоминания пересчитываются.

### Задействованные модули

- Frontend: `features/lessons/ui/LessonForm/`, `features/lessons/models/lesson-form.model.ts`, `features/lessons/models/lesson-form.helpers.ts`
- Backend: `controllers/lessons/createLesson.ts` (`POST /api/lessons`), `services/recurringLessons.ts` (cron daily 2AM), `services/recurringHelpers.ts`, `controllers/lessons/updateLesson.ts`

### Наблюдаемый результат

В БД ~13 уроков за 3 месяца; ежедневное продление; каскадный сдвиг при смене времени.

### Почему важен

Большинство учеников занимаются регулярно — это основной способ ведения расписания.

### Что покрыто сейчас

Покрытия нет. Cron, скорее всего, потребует ручного триггера через test endpoint или time-mocking.

## 13. Расчёт налога за период с несколькими историческими ставками

- **Приоритет:** Critical
- **Статус:** uncovered
- **Тег:** `@reports`

### Шаги journey

1. Учитель задаёт диапазон дат, охватывающий смену ставки (например, часть уроков 4%, часть 6%), нажимает «Обновить».
2. `GET /api/statistics?startDate=&endDate=` — при `taxEnabled=true` запрашивает `paidLessonsForTax` и `taxRatePeriods` пользователя.
3. `buildTaxBreakdown` (`services/taxRate.ts`): через `resolveRate` распределяет уроки по бакетам ставок, считает `calcLessonTax(price, rate) = round(price * rate / 100)`, собирает массив + `taxAmount`.
4. Если ставок > 1 или есть платежи до первого периода — `FinancialStatistics` показывает `TaxRateInfoTooltip` с разбивкой.

### Задействованные модули

- Frontend: `pages/ReportsPage/components/FinancialStatistics/`, `pages/ReportsPage/components/FinancialStatistics/FinancialStatistics.helpers.ts`
- Backend: `controllers/statistics/getStatistics.ts`, `services/taxRate.ts` (`buildTaxBreakdown`, `resolveRate`, `calcLessonTax`, `computeRatesInRange`)

### Наблюдаемый результат

Карточка «Налоги» с суммой; при смешанных ставках — тултип с таблицей по бакетам.

### Почему критичен

Ошибка в `resolveRate` или граничных датах периодов → учитель перечислит неверную сумму налога в ФНС.

### Что покрыто сейчас

## 23. Подписка на push-уведомления и получение напоминания об уроке

- **Приоритет:** Critical
- **Статус:** uncovered
- **Тег:** `@push`

### Шаги journey

1. Профиль → «Напоминания об уроках» — компонент `ReminderSettings`.
2. При инициализации регистрируется `/push-sw.js`, загружаются VAPID-ключ (`GET /api/push/vapid-key`) и настройки (`GET /api/reminder-settings`).
3. Учитель включает тумблер → `Notification.requestPermission()` → `pushManager.subscribe(...)` с VAPID → `POST /api/push/subscribe` (upsert по `endpoint`).

### Задействованные модули

### Наблюдаемый результат

## 24. Live-обновление статуса урока через WebSocket

- **Приоритет:** High
- **Статус:** uncovered
- **Тег:** `@realtime`

### Шаги journey

1. После логина — `connectWebSocketFx` устанавливает `wss://.../ws?token=<JWT>`.
2. Бэк `WebSocketManager.handleConnection` аутентифицирует, регистрирует клиента в `Map<userId, ws>`.
3. Cron `updateLessonStatuses` обнаруживает урок (`startTime <= now < endTime`) → обновляет статус в БД → `wsManager.broadcastLessonStatusUpdate(lessonId, "IN_PROGRESS", tutorId)`.
4. `sendToUser` посылает `{type: "lesson_status_updated", lessonId, status}`.
5. Клиент `handleLessonStatusUpdate` → `lessonModel.updateLesson` — стор реактивно обновляется.
6. При разрыве — `reconnectTimeoutFx` (5 сек) автоматически реконнектит.

### Задействованные модули

- Frontend: `app/App.tsx`, `app/model/web-socket.model.ts`
- Backend: `lib/websocket/WebSocketManager.ts` (`WS /ws`), `services/lessonStatusUpdater.ts` (cron minutely), `controllers/lessons/updateLesson.ts`, `controllers/lessons/createLesson.ts`

### Наблюдаемый результат

Статус урока меняется автоматически без перезагрузки; ручное изменение мгновенно отражается на других вкладках.

### Почему важен

Без этого учитель видит устаревшие данные → дубли «отметить урок» или незамеченные автозавершения.

### Что покрыто сейчас

Покрытия нет. **E2E-сложность:** Средняя — Playwright поддерживает несколько контекстов и `page.on('websocket', ...)`; cron нужно мокировать или триггерить вручную через test endpoint.
