## Находки

### 1. На телефоне демонстрация вертикального окна мелкая, а плашка перекрывает содержимое

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** S2, P3.1
- **Файл/место:** `frontend/src/features/videoCall/ui/ActiveCallScreen/ActiveCallScreen.styled.ts:51` (`aspectRatio: "16 / 9"` у основной плитки), `frontend/src/features/videoCall/ui/VideoTile/VideoTile.tsx` (плашка «Демонстрация экрана» и имя поверх видео)
- **Однозначность исправления:** нет

#### Шаги

1. Ученик на телефоне 375×812, активный звонок.
2. Репетитор демонстрирует вертикальное окно 800×1000.

#### Ожидание (US3-1)

Собеседник видит транслируемое содержимое и может его прочитать.

#### Реальность

Фикс run 1 работает: окно видно целиком (`contain`). Но плитка собеседника на телефоне фиксированно 16:9 (333×186), поэтому вертикальное окно занимает ~150×186 px, а сверху над плиткой ~250 px пустого места. Плашка «Демонстрация экрана» лежит на верхней строке содержимого («ЗАДАЧА №1» перекрыта), имя собеседника — на нижней. На десктопе плашки попадают на поля и не мешают.

#### Скриншоты

![Мобильная демонстрация вертикального окна](./2026-10-19-030-webrtc-video-calls-run2/screenshots/38-mobile-peer-portrait-share.png)

#### Console / Network

```
student remote <video>: stream 800x1000, box 333x186, object-fit: contain
```

#### Предлагаемое исправление

Для демонстрации экрана на узком экране отдавать плитке всю высоту сцены (без `aspectRatio: 16/9`), а плашку и имя выносить за пределы видео или делать полупрозрачными в углу. Это решение по раскладке экрана звонка.

### 2. Открытая история звонков не обновляется после завершённого звонка

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** P4.5
- **Файл/место:** `frontend/src/entities/callRecord/model/callHistory.model.ts` (загрузка только на `CallHistoryGate.open`); `backend/src/services/callSignaling/callSignaling.ts` (`terminateCall` пишет запись после уведомления сторон)
- **Однозначность исправления:** нет

#### Шаги

1. Ученик открыл «История звонков» (`/student/cabinet/calls`).
2. Репетитор звонит, ученик отклоняет вызов прямо на этой странице.

#### Ожидание

Только что отклонённый звонок появляется в открытом списке.

#### Реальность

Список остаётся прежним (первая строка до и после: «Пропущен / Исходящий / 22:12»), новая запись видна только после перехода или перезагрузки.

#### Console / Network

```
GET /api/student/calls/history — только при открытии страницы, после звонка запросов нет
```

#### Предлагаемое исправление

Перезагружать историю при завершении звонка, пока страница открыта. Простой refetch на `callResourcesReleased` гонится с сервером: запись создаётся после отправки `call_ended`, а у стороны, нажавшей «Завершить», ещё раньше. Нужна задержка или серверное событие о новой записи, поэтому это не автофикс.

### 3. При ошибке загрузки история звонков показывает «Звонков пока нет»

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** P4.5
- **Файл/место:** `frontend/src/entities/callRecord/model/callHistory.model.ts` (на `loadCallHistoryFx.fail` список сбрасывается в `[]`), `frontend/src/features/videoCall/ui/CallHistoryList/CallHistoryList.tsx:14`
- **Однозначность исправления:** нет

#### Шаги

1. Открыть `/call/history`, когда `GET /api/calls/history` отвечает 500 (эмуляция через `page.route`).

#### Ожидание (SC-007)

Понятно, что история не загрузилась, а не что звонков нет.

#### Реальность

Тост «Не удалось загрузить историю звонков» исчезает через ~4 с, а на странице остаётся пустое состояние «Звонков пока нет. Здесь появится история ваших видеозвонков». Пользователь может решить, что история пропала. Во время загрузки (> 300 мс) пустое состояние тоже видно под глобальным оверлеем — это общий паттерн приложения, отдельно не репорчу.

```
GET /api/calls/history 500 → toast «Не удалось загрузить историю звонков», в списке «Звонков пока нет»
```

#### Предлагаемое исправление

Хранить флаг ошибки загрузки (`$loadFailed`, сброс на `loadCallHistoryFx`) и показывать вместо пустого состояния сообщение об ошибке с кнопкой «Повторить». Нужны вид и текст состояния ошибки.
