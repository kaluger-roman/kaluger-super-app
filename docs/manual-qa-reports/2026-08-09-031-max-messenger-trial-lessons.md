## Находки

### 1. Привязка пробного урока к ученику молча подменяет цену 0 на ставку ученика

- **Категория:** ❌ Spec mismatch
- **Severity:** High
- **Сценарий:** P3.1
- **Файл/место:** `frontend/src/features/lessons/models/lesson-form.helpers.ts` (`applyWithoutStudentRules`, сброс цены при выключении toggle) + `applyHourlyRateAutofill`
- **Однозначность исправления:** да

#### Шаги
1. Создать пробный урок без ученика (цена по умолчанию 0).
2. Открыть урок → Редактировать → снять галочку «Пробный урок без ученика».
3. Выбрать существующего ученика (ставка 1000 ₽) → «Обновить урок».

#### Ожидание (spec.md, US3 AS1/AS3)
Урок привязывается «с исходной датой, ценой и статусом»; «урок по-прежнему
считается пробным (цена 0), двойного учёта нет».

#### Реальность
Цена урока стала 1000 ₽ (ставка ученика). В БД: `price: "1000"`. Урок выпал
из счётчика пробных и попал в потенциальный доход. Причина: при выключении
toggle цена "0" сбрасывается в пустую строку, после чего выбор ученика
запускает автозаполнение ставкой (`applyHourlyRateAutofill`), и PUT уходит
с price=1000.

#### Скриншоты
![](./2026-08-09-031-max-messenger-trial-lessons/screenshots/07-linking-student-selected.png)

#### Console / Network
```
PUT /api/lessons/cmskw7tju00058zv4miqh2n9v 200 — payload содержал price: 1000
```

#### Предлагаемое исправление
Сбрасывать цену при выключении toggle только в режиме создания
(нет `editingLesson`); при редактировании существующего prospect-урока
сохранять текущую цену — тогда автозаполнение ставкой не сработает
и привязка сохранит исходную цену.

### 3. Проп `$drawerWidth` утекает в DOM — console error на каждой странице

- **Категория:** 🐛 Bug
- **Severity:** Low
- **Сценарий:** любой (ошибка в консоли при открытом сайдбаре)
- **Файл/место:** `frontend/src/widgets/sidebar/Sidebar.styled.ts:12` — `styled` импортирован из `@mui/material` вместо `@shared` (без фильтрации `$`-пропов)
- **Однозначность исправления:** да

#### Шаги
1. Открыть любую страницу приложения, открыть сайдбар (бургер-меню).
2. Открыть консоль браузера.

#### Ожидание
Консоль чистая.

#### Реальность
```
[ERROR] React does not recognize the `$drawerWidth` prop on a DOM element...
[ERROR] Invalid attribute name: `$drawerWidth`
```

Не относится к фиче 031 (существующее), но причина однозначна: конвенция
проекта требует `styled` из `@shared` (фильтрует `$`-пропы), а
`Sidebar.styled.ts` использует `styled` из `@mui/material`. Соседний
`StudentSidebar.styled.ts` делает правильно.

#### Скриншоты
Текстовая находка (ошибка консоли), скриншот не требуется.

#### Предлагаемое исправление
Импортировать `styled` из `@shared` в `Sidebar.styled.ts`.

### 4. Диалог редактирования урока не закрывается после успешного сохранения

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** P3.1 (замечено при привязке; воспроизведено и на обычном изменении цены)
- **Файл/место:** механика закрытия `LessonForm` после `updateLesson` (существующее поведение, фичей не менялось)
- **Однозначность исправления:** нет (воспроизводится на любом обновлении урока — возможно намеренное поведение; менять flow — решение PO)

#### Шаги
1. Открыть урок → Редактировать → изменить любое поле → «Обновить урок».

#### Ожидание
Диалог закрывается, список обновлён.

#### Реальность
PUT проходит (200), список за диалогом обновляется, но диалог
«Редактировать урок» остаётся открытым — пользователь закрывает вручную
через «Отмена». Одинаково для обычных и пробных уроков → не регрессия
фичи 031.

#### Скриншоты
Поведенческая находка; зафиксирована сетевым логом (PUT 200 + открытый диалог в снапшоте DOM).
