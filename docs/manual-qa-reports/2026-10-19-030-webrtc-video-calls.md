- **Сценарий:** P3.1
- **Файл/место:** `frontend/src/features/videoCall/ui/VideoTile/VideoTile.styled.ts:35` (`objectFit: "cover"` для любого видео), `TileContent.tsx`

2. Репетитор демонстрирует окно 800×1000 (вертикальный документ: заголовок «ЗАДАЧА №1» сверху, «Ответ» снизу).

### 2. Звонок, завершённый или оборванный собеседником, закрывается молча

- **Категория:** ⚠️ UX issue
- **Severity:** Medium
- **Сценарий:** E2, E6 (FR-016, SC-007)
- **Файл/место:** `frontend/src/features/videoCall/model/toasts.model.ts` (для `callEnded` уведомления нет); сервер шлёт один и тот же `call_ended` при hangup, обрыве WS и отказе устройств (`backend/src/lib/websocket/signaling.ts`)
- **Однозначность исправления:** нет

#### Шаги

1. Активный звонок репетитор ↔ ученик; ученик закрывает вкладку.
2. Отдельно: ученик принимает вызов без доступа к камере и микрофону (или наоборот, у репетитора нет устройств).

#### Ожидание (FR-016, Edge «Нет доступа ни к камере, ни к микрофону», SC-007)

Второй участник видит, что собеседник отключился / звонок невозможен, и получает понятное сообщение.

#### Реальность

У второй стороны полноэкранный звонок просто исчезает за ~40 мс, без тоста и баннера. Сообщение «Нет доступа к камере и микрофону» видит только участник без устройств. Если у репетитора нет устройств, ученик после «Принять» молча возвращается на расписание и не понимает, что произошло. Обычное «Завершить» собеседником выглядит так же, поэтому обрыв от штатного завершения не отличить.

#### Скриншоты

![Репетитор после завершения звонка собеседником](./2026-10-19-030-webrtc-video-calls/screenshots/18-tutor-idle-after-peer-hangup.png)

#### Console / Network

```
tutor  << call_ended   (ученик закрыл вкладку; тостов: [])
student << call_ended  (у репетитора нет устройств; тостов у ученика: [])
```

#### Предлагаемое исправление

Различать причину на сервере (например, `call_ended { reason: "hangup" | "peer_disconnected" | "media_unavailable" }`) и показывать «Собеседник завершил звонок» / «Собеседник отключился» / «У собеседника нет доступа к камере и микрофону». Это меняет контракт сигналинга и тексты, поэтому нужно решение.

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** P1.2
- **Файл/место:** `frontend/src/features/videoCall/ui/IncomingCallModal/IncomingCallModal.tsx:22` (`onClose={() => actions.reject()}`)
- **Однозначность исправления:** да

#### Шаги

1. Репетитор звонит ученику, у ученика открыто окно «Входящий вызов».

#### Ожидание

Случайный тап мимо кнопок не должен сбрасывать вызов: «Отклонить» — отдельная красная кнопка.

#### Реальность

Окно закрывается, на сервер уходит `call_reject`, у репетитора «Вызов отклонён», в истории «Отклонён». На телефоне случайно попасть по фону вокруг небольшой карточки легко.

#### Скриншоты

![Окно входящего вызова](./2026-10-19-030-webrtc-video-calls/screenshots/05-student-incoming-call.png)

```

tutor toast: «Вызов отклонён»
```

#### Предлагаемое исправление

В `onClose` игнорировать `reason === "backdropClick"`; Esc (осознанное действие с клавиатуры) оставить как отклонение.

### 6. У адресата пропущенный по таймауту вызов называется «Вызов отменён»

- **Категория:** ⚠️ UX issue
- **Severity:** Low
- **Сценарий:** P1.7
- **Файл/место:** `backend/src/lib/websocket/signaling.ts` (`onRingTimeout` шлёт адресату `call_canceled`), `frontend/src/features/videoCall/model/toasts.model.ts` (`CANCELED_TEXT`)
- **Однозначность исправления:** нет

#### Шаги

1. Репетитор звонит, ученик не отвечает 40 с.

#### Ожидание

Ученик понимает, что пропустил вызов (в его истории запись «Пропущен»).

#### Реальность

У звонящего «Нет ответа» (верно), а у ученика тост «Вызов отменён», хотя репетитор ничего не отменял. Тост расходится с историей.

#### Console / Network

```

```

#### Предлагаемое исправление

Отдельный сигнал или причина для таймаута (например, `call_canceled { reason: "timeout" }`) и текст «Пропущенный вызов от …». Затрагивает контракт сигналинга.

На экране «Вызываем…» есть только «Отменить», в окне входящего вызова только «Принять»/«Отклонить». Медиа всегда стартует с включёнными камерой и микрофоном, выключить их можно только после соединения. Сама передача индикаторов при установлении соединения работает (`call_media_state` уходит сразу после получения медиа, проверено на P2.6).
