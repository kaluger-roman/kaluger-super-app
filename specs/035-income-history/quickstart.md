# Quickstart: 035-income-history

Как поднять фичу локально, применить миграцию и вручную проверить
сценарии спеки.

## 1. Окружение

Ветка `035-income-history` (worktree
`.claude/worktrees/detalizaciya-postuplenij-tmp`). В свежем worktree:

```bash
ls -l frontend/node_modules backend/node_modules   # симлинки из основного чекаута
ls backend/.env backend/.env.test                  # скопированы из основного чекаута
```

Дев-стек ветки (свой Postgres и порты): `scripts/dev-stack.sh up`.

## 2. Миграция

```bash
cd backend
npx prisma migrate dev --create-only --name add_lesson_received_amount
# дописать в migration.sql после ALTER TABLE:
#   UPDATE "lessons" SET "receivedAmount" = COALESCE("price", 0) WHERE "isPaid" = true;
npm run db:migrate
npm run db:generate
npm run db:migrate:test
```

Проверка бэкфилла и инварианта (FR-021, SC-006):

```sql
SELECT COUNT(*) FROM lessons WHERE "isPaid" AND "receivedAmount" IS NULL;           -- 0
SELECT COUNT(*) FROM lessons WHERE NOT "isPaid" AND "receivedAmount" IS NOT NULL;   -- 0
SELECT COUNT(*) FROM lessons WHERE "isPaid" AND "receivedAmount" <> COALESCE("price", 0); -- 0
```

Сверка «до/после» (SC-006): до миграции сохранить ответ
`GET /api/statistics` за текущий месяц, прошлый месяц и год; после миграции
те же запросы должны дать идентичный JSON (кроме полей, которых раньше
не было).

## 3. Запуск

```bash
cd backend && npm run dev     # http://localhost:3001 (или порт слота dev-stack)
cd frontend && npm start      # http://localhost:3000
```

Профиль → включить «Учитывать налог», период ставки 6% с начала года.
Одному ученику задать комиссию 3000 ₽.

## 4. Ручная проверка по историям

### US1: история по дням

1. Отметить оплаченными: два урока одного ученика 3-го числа (по 1500 ₽),
   урок другого ученика 5-го (2000 ₽).
2. Отчёты: активна «Сводка», в карточке «Поступления за период» ссылка
   «История поступлений по дням». Нажать: открылась вкладка «История
   поступлений», страница прокрутилась к вкладкам.
3. Два дня: 5-е (2 000 ₽), затем 3-е (3 000 ₽, две строки одного ученика
   рядом); итог 5 000 ₽ и 3 оплаты = карточка.
4. Сменить период на прошлый месяц и нажать «Обновить» на вкладке
   истории: вкладка не сменилась, история и карточки — прошлого месяца.
5. Уйти на «Уроки» и вернуться: активна «История поступлений».
   Перезагрузить браузер: активна «Сводка». URL вкладку не содержит.
6. Пустой период: «За выбранный период поступлений нет».
7. DevTools → блокировать `/api/statistics/income-history`, «Обновить»:
   на вкладке истории сообщение об ошибке, карточки сводки на месте.
8. Год с 120+ оплатами (сидировать через test-support или скриптом):
   итог сразу за весь период; под списком «Показать ещё (осталось N)»;
   нажать — кнопка «Загружаем оплаты…» без общего оверлея, дни
   дописались, список не прыгнул; заблокировать запрос и нажать снова —
   показанные оплаты на месте, сообщение и «Повторить».
9. 375px: обе вкладки в строку, итог плитками 2×2, длинное имя не ломает
   строку, горизонтальной прокрутки нет.

### US2: полученная сумма

1. Урок 2000 ₽ → попап → переключатель оплаты: в диалоге «Дата оплаты»
   и «Получено» = 2000. Подтвердить. Поменять цену на 2500: в истории
   2 000 ₽ и значок, подсказка «Получено 2 000 ₽, стоимость урока 2 500 ₽»;
   карточка «Поступления» не изменилась; в попапе «получено 2 000 ₽».
2. Форма редактирования этого урока: «Получено (₽)» рядом с «Датой
   оплаты» = 2000. Ввести 2500, сохранить: значка нет, дата оплаты прежняя.
3. Другой урок 2000 ₽ отметить через значок на карточке списка, ввести
   1800: в истории 1 800 ₽ со значком, карточка учитывает 1800, долг
   по ученику не появился.
4. В диалоге очистить поле → «Укажите полученную сумму», «Подтвердить»
   неактивна, Enter ничего не делает; ввести `-5` → «Сумма должна быть
   неотрицательным числом».
5. Снять оплату и отметить снова: «Получено» по умолчанию = текущая цена.
6. Неоплаченный урок: в форме поменять цену на 2500 и переключить
   оплату — в диалоге «Получено» = 2500.
7. Регулярная серия: предоплатить будущий урок, поменять цену серии —
   у предоплаченного урока в истории прежняя сумма и значок.
8. Отменить оплаченный урок с переносом на следующий урок ученика:
   в диалоге отмены сумма переноса = полученная; в истории оплата у
   урока-получателя с прежней датой и полученной суммой отменённого.
9. Кабинет ученика: в уроках нет полученной суммы (DevTools → ответ
   `/api/student-cabinet/lessons` без `receivedAmount`).

### US3: налог и комиссия

1. Уроки 1000 ₽, 2000 ₽ «Не облагается налогом», урок ученика с комиссией
   на 1500 ₽: строки «налог 60 ₽ · 6%», «0% без налога», «налог 90 ₽ · 6%»
   и «в счёт комиссии 1 500 ₽». Итог: налог 150 ₽ (= карточка), в счёт
   комиссий 1 500 ₽ (= «Списано в счёт комиссий»), необлагаемые 2 000 ₽.
2. Поднять цену первого урока до 1200: налог по нему 60 ₽.
3. Оплата до первого периода ставки: «налог 0 ₽ · вне настроенных периодов».
4. Выключить учёт налога: налога, ставок и «без налога» в истории нет.
5. Убрать комиссию у ученика: ни одной пометки и плитки про комиссии.

### US4: переход к уроку

1. Нажать на строку: открылся попап именно этого урока поверх вкладки.
   Закрыть: та же вкладка, период, порции и прокрутка.
2. Из попапа снять оплату: строка исчезла, итог и карточки пересчитались
   без перезагрузки. Поменять дату оплаты на день другого периода: строка
   ушла. Поменять стоимость: сумма та же, значок появился.
3. Из попапа «Отменить», «Перенести», «Удалить»: открываются те же
   диалоги, что на странице уроков; после действия история обновлена.
4. Удалить урок в другой вкладке, нажать на его строку: «Урок не найден…»,
   история обновилась.
