# Feature Specification: Заметки урока в карточке списка

**Feature Branch**: `032-lesson-notes-in-card`
**Created**: 2026-09-04
**Status**: Draft
**Input**: User description: "у урока есть заметки, нужно сделать их видимым в карточке урока в списке, но чтоб это не выглядело очень масштабно, то есть если длинно, дать возможность разворачивания заметки на десктопе, на мобиле тоже подумать как это лучше сделать, задача - сделать заметки реально полезными, сейчас ими не пользуются, потому что для их просмотра надо открывать попап урока каждый раз"

## Clarifications

### Session 2026-09-04

- Q: Как определяется, что заметка «обрезана» и нужно показать элемент разворачивания? → A: Компактный вид ограничен CSS line-clamp в 2 строки; элемент разворачивания показывается только когда фактический контент переполняет обрезанную высоту (измеряется scrollHeight > clientHeight), а не по числу символов. Это устойчиво к разной ширине карточки, длинным словам и переносам строк.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Заметка видна прямо в карточке урока (Priority: P1)

Репетитор ведёт заметки к урокам (что проходили, что задать, особенности
ученика), но сейчас, просматривая список уроков, он их не видит: чтобы
прочитать заметку, нужно открыть попап каждого урока по отдельности.
Из-за этого заметками фактически не пользуются. Теперь, если у урока есть
заметка, её начало отображается прямо в карточке урока в списке уроков —
компактно, не раздувая карточку. Репетитор пролистывает список и сразу
видит, к каким урокам что записано, без единого лишнего клика.

**Why this priority**: Это ядро фичи — вернуть заметкам полезность.
Пока заметка не видна без открытия попапа, остальные улучшения не имеют
смысла.

**Independent Test**: Создать урок с короткой заметкой (одна строка),
открыть список уроков — текст заметки виден в карточке целиком без
каких-либо действий. Создать урок без заметки — его карточка выглядит
как раньше, без пустого блока под заметку.

**Acceptance Scenarios**:

1. **Given** урок с короткой заметкой, **When** репетитор открывает список
   уроков, **Then** текст заметки виден в карточке урока полностью,
   без дополнительных кликов
2. **Given** урок без заметки, **When** репетитор открывает список уроков,
   **Then** в карточке нет блока заметки и она не занимает лишнего места
   (выглядит как до внедрения фичи)
3. **Given** урок с длинной заметкой, **When** репетитор открывает список
   уроков, **Then** в карточке показано только начало заметки (компактный
   фрагмент ограниченной высоты), и по виду карточки понятно, что текст
   обрезан и его можно раскрыть
4. **Given** карточка урока с заметкой, **When** репетитор кликает по самой
   карточке (не по элементу управления заметкой), **Then** как и раньше
   открывается окно просмотра урока, где заметка показана целиком
5. **Given** заметка состоит только из пробелов/пустых строк, **When**
   репетитор открывает список уроков, **Then** блок заметки в карточке
   не отображается

### User Story 2 - Разворачивание длинной заметки на месте (Priority: P2)

У части уроков заметки длинные (план занятия, разбор ошибок). Репетитор
на десктопе видит в карточке начало заметки и элемент разворачивания.
Нажав его, он раскрывает полный текст заметки прямо в карточке, читает
и сворачивает обратно — окно урока при этом не открывается, позиция
в списке не теряется.

**Why this priority**: Без разворачивания длинные заметки по-прежнему
требовали бы открытия попапа, то есть проблема решалась бы только для
коротких заметок.

**Independent Test**: Создать урок с заметкой в несколько абзацев, в списке
уроков развернуть заметку по элементу разворачивания — виден весь текст
с переносами строк; свернуть — карточка вернулась к компактному виду;
попап урока при этих действиях не открывался.

**Acceptance Scenarios**:

1. **Given** карточка урока с обрезанной длинной заметкой, **When**
   репетитор нажимает элемент разворачивания, **Then** полный текст
   заметки раскрывается прямо в карточке, переносы строк сохранены
2. **Given** развёрнутая заметка в карточке, **When** репетитор нажимает
   элемент сворачивания, **Then** карточка возвращается к компактному
   виду с обрезанным фрагментом
3. **Given** карточка урока с заметкой, **When** репетитор нажимает
   на элемент разворачивания/сворачивания, **Then** окно просмотра урока
   НЕ открывается (открытие попапа происходит только по клику по остальной
   области карточки)
4. **Given** заметка короткая и видна целиком, **When** репетитор смотрит
   на карточку, **Then** элемент разворачивания не отображается
5. **Given** несколько карточек с длинными заметками, **When** репетитор
   разворачивает заметку одного урока, **Then** заметки остальных уроков
   остаются свёрнутыми (состояние независимо для каждой карточки)

### User Story 3 - Удобный просмотр заметок на мобильном (Priority: P3)

Репетитор часто смотрит расписание с телефона между занятиями. На узком
экране карточка урока и так плотная, поэтому заметка отображается так же
компактно (начало текста), а полный текст раскрывается касанием элемента
разворачивания — зона касания достаточная, случайное открытие попапа
урока при попытке развернуть заметку не происходит.

**Why this priority**: Мобильный сценарий важен (пользователь явно его
выделил), но строится поверх поведения из историй 1–2 и уточняет его
для касаний и узких экранов.

**Independent Test**: Открыть список уроков на мобильной ширине экрана,
найти урок с длинной заметкой: виден компактный фрагмент; касание элемента
разворачивания раскрывает текст на месте, попап не открывается; касание
остальной области карточки открывает попап, как раньше.

**Acceptance Scenarios**:

1. **Given** мобильная ширина экрана и урок с длинной заметкой, **When**
   репетитор смотрит список уроков, **Then** заметка показана компактным
   фрагментом и не ломает вёрстку карточки (текст не вылезает за границы)
2. **Given** мобильная ширина экрана, **When** репетитор касается элемента
   разворачивания заметки, **Then** полный текст раскрывается в карточке,
   а окно просмотра урока не открывается
3. **Given** мобильная ширина экрана и развёрнутая заметка, **When**
   репетитор касается элемента сворачивания, **Then** заметка сворачивается
   к компактному фрагменту

---

### Edge Cases

- Заметка без пробелов из одного очень длинного «слова» (например, ссылка) —
  текст обрезается по ширине карточки и не растягивает вёрстку
- Очень длинная заметка (тысячи символов) — карточка в развёрнутом виде
  показывает весь текст, список остаётся прокручиваемым и отзывчивым
- Заметка ровно на границе лимита компактного фрагмента — элемент
  разворачивания показывается только если текст реально обрезан
- Заметка с переносами строк, укладывающаяся в лимит по длине, но
  многострочная — компактный фрагмент ограничен по высоте, остальное
  доступно через разворачивание
- Обновление заметки в реальном времени (заметку изменили в другом окне) —
  карточка показывает актуальный текст
- Список с большим количеством уроков с заметками — карточки остаются
  компактными, пока заметки не развёрнуты
- Уроки в недельном виде списка — заметка отображается по тем же правилам,
  что и в обычном списке (используется та же карточка урока)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Карточка урока в списке уроков MUST отображать текст заметки,
  если заметка урока непуста (после отбрасывания пробельных символов)
- **FR-002**: Компактный вид заметки MUST быть ограничен по высоте
  (порядка 1–2 строк текста), чтобы карточки в списке не разрастались
- **FR-003**: Если текст заметки не помещается в компактный вид, карточка
  MUST показывать элемент разворачивания; если помещается целиком —
  элемент разворачивания MUST отсутствовать. Компактный вид ограничивается
  CSS line-clamp в 2 строки; факт обрезки определяется переполнением
  (`scrollHeight > clientHeight`), а не числом символов
- **FR-004**: Пользователь MUST иметь возможность развернуть заметку
  до полного текста прямо в карточке и свернуть её обратно; переносы строк
  в развёрнутом виде MUST сохраняться
- **FR-005**: Нажатие/касание элемента разворачивания или сворачивания
  MUST NOT открывать окно просмотра урока; клик по остальной области
  карточки MUST открывать окно просмотра урока, как раньше
- **FR-006**: Состояние развёрнутости MUST быть независимым для каждой
  карточки; по умолчанию заметки свёрнуты
- **FR-007**: У уроков без заметки карточка MUST выглядеть без изменений —
  никаких пустых блоков или дополнительных отступов
- **FR-008**: Поведение MUST работать и на десктопной, и на мобильной
  ширине экрана; на мобильном элемент разворачивания MUST иметь
  достаточную зону касания
- **FR-009**: Заметка MUST отображаться по одним и тем же правилам во всех
  представлениях списка уроков, где используется карточка урока
  (группировка по датам и недельный вид)
- **FR-010**: Существующий просмотр полной заметки в окне урока MUST
  остаться без изменений

### Key Entities

- **Урок**: занятие репетитора с учеником; имеет опциональную заметку —
  свободный многострочный текст без ограничения длины, задаваемый при
  создании/редактировании урока. Фича только отображает заметку,
  не меняет способы её редактирования и хранения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Репетитор читает короткую заметку урока из списка за 0 кликов,
  длинную — за 1 клик (разворачивание), вместо открытия попапа на каждый
  урок
- **SC-002**: Просмотр заметок 10 уроков подряд в списке занимает менее
  30 секунд (раньше — 10 открытий и закрытий попапа)
- **SC-003**: Высота карточки урока со свёрнутой заметкой увеличивается
  не более чем на 2 строки текста относительно карточки без заметки
- **SC-004**: 100% карточек уроков без заметок визуально не отличаются
  от текущего вида
- **SC-005**: Разворачивание и сворачивание заметки ни в одном из случаев
  не приводит к открытию окна просмотра урока

## Assumptions

- Компактная ячейка урока в сеточном виде расписания (недельная сетка
  с ячейками) вне рамок фичи: там слишком мало места даже для фрагмента
  заметки. Фича касается карточек урока в списке (включая недельный вид
  списка, использующий ту же карточку).
- На мобильном используется тот же паттерн «фрагмент + разворачивание
  на месте», а не отдельный экран/шторка: это решает задачу и не добавляет
  новых навигационных состояний. Отличие от десктопа — только требования
  к зоне касания.
- Состояние развёрнутости не сохраняется между визитами/перезагрузками —
  по умолчанию заметки всегда свёрнуты.
- Редактирование заметок остаётся в форме урока (попапе) — фича только
  про просмотр в списке.
- Правила распространяются на все типы уроков, включая пробные уроки
  без ученика.
