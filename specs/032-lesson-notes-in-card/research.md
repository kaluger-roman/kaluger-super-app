# Phase 0 Research: Заметки урока в карточке списка

Все NEEDS CLARIFICATION из Technical Context разрешены. Фича frontend-only,
реализована на этапе mockup; исследование фиксирует принятые решения.

## R1. Определение обрезки заметки (когда показывать «Развернуть»)

- Decision: Компактный вид — CSS line-clamp (`display: -webkit-box`,
  `-webkit-line-clamp: 2`, `-webkit-box-orient: vertical`, `overflow: hidden`).
  Факт обрезки определяется измерением DOM: `scrollHeight > clientHeight + 1`
  через хук `useIsTextClamped` с `useLayoutEffect` и `ResizeObserver` для
  пересчёта при ресайзе карточки. Контрол разворачивания показывается, если
  `expanded || isClamped`.
- Rationale: Устойчиво к любой ширине карточки, длинным словам-ссылкам и
  переносам строк — в отличие от порога по числу символов, который ломается при
  разной ширине и многострочном тексте. Соответствует Clarification в spec.md
  (Session 2026-09-04) и FR-002/FR-003.
- Alternatives considered: (а) порог по количеству символов — отклонён:
  зависит от шрифта/ширины, даёт ложные срабатывания; (б) всегда показывать
  контрол — отклонён: нарушает FR-003 (короткая заметка без контрола) и
  US1/US2 сценарии.

## R2. Хранение состояния развёрнутости (Effector vs локальный useState)

- Decision: Локальный `useState(expanded)` внутри `LessonNotes` — состояние
  независимо для каждой карточки, по умолчанию свёрнуто, не персистится.
- Rationale: Это transient UI-стейт одной карточки, не доменные данные и не
  форма. Конституция (III) требует Effector для frontend state, но принцип VII
  (Simplicity, YAGNI, no premature abstraction) приоритетен для сугубо
  локального toggle: вынос в Effector-стор на карточку добавил бы сложность без
  выгоды. FR-006 (независимость на карточку, дефолт свёрнуто) и Assumption
  «состояние не сохраняется между визитами» естественно ложатся на `useState`.
  Это утверждённый на этапе mockup финальный дизайн.
- Alternatives considered: (а) Effector-стор с ключом по lessonId — отклонён:
  over-engineering для transient toggle, лишний код и тесты; (б) поднять стейт
  в `LessonCard` — отклонён: не нужно, инкапсуляция в `LessonNotes` чище.

## R3. Предотвращение открытия попапа при клике на контрол

- Decision: Обработчик `handleToggle` вызывает `event.stopPropagation()` перед
  переключением `expanded`; контрол — семантический `<button type="button">`.
- Rationale: Клик по карточке открывает попап через всплытие до кликабельной
  области карточки; `stopPropagation` на кнопке разрывает всплытие — FR-005,
  US2 сценарий 3, US3 сценарий 2, SC-005. `type="button"` исключает сабмиты.
- Alternatives considered: `preventDefault` — недостаточно (не гасит
  всплытие к обработчику карточки).

## R4. Мобильная зона касания и перенос строк

- Decision: `ToggleButton` имеет `minHeight: 32` и вертикальный паддинг —
  достаточная зона касания на мобильном (FR-008). Текст: `whiteSpace: pre-wrap`
  (сохранение переносов строк в развёрнутом виде — FR-004) и
  `overflowWrap: anywhere` (длинное слово/ссылка не растягивает вёрстку —
  Edge Cases).
- Rationale: Тот же паттерн «фрагмент + разворачивание на месте» на десктопе и
  мобильном (Assumptions), отличие только в зоне касания.
- Alternatives considered: отдельная мобильная шторка/экран — отклонён
  явным Assumption спеки.

## R5. Реал-тайм обновление и переиспользование во всех представлениях

- Decision: `LessonNotes` — чистый презентационный компонент, получает `notes`
  из модели урока (`lesson.notes`) через `LessonCard`. Актуальность текста
  обеспечивается существующим потоком данных списка (Effector-стор уроков,
  обновляемый по WebSocket) — отдельной логики не требуется. `LessonCard`
  переиспользуется всеми представлениями списка (группировка по датам,
  недельный вид списка), поэтому правила отображения единые (FR-009).
- Rationale: Компонент stateless по данным (только по toggle), поэтому смена
  `notes` в сторе перерисовывает карточку с актуальным текстом (Edge Case
  «обновление в реальном времени»). Компактная ячейка в сеточном недельном
  расписании вне рамок фичи (Assumptions).
- Alternatives considered: подписка `LessonNotes` на стор напрямую — отклонён:
  нарушил бы презентационную чистоту и FSD, дублировал бы поток данных.
