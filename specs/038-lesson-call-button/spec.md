# Feature Specification: Звонок как атрибут урока

**Feature Branch**: `038-lesson-call-button`
**Created**: 2026-10-23
**Status**: Draft
**Input**: User description: "кнопка позвонить должна быть у репетитора еще в карточках самого урока (сейчас только у ученика), ученик имеет кнопку позвонить сверху в главнмо меню, что странно, звонок тоже должен быть атрибутом урока, ученик не должен звонить одной главной кнопкой"

## Clarifications

### Session 2026-10-23

- Q: Где кнопка звонка по уроку — на карточке в списке или в попапе урока? → A: В попапе урока (окно просмотра урока), у репетитора и у ученика. На карточках в списках кнопки нет.
- Q: Нужна ли защита от случайного звонка? → A: Да, любой исходящий звонок начинается только после подтверждения.
- Q: Ограничивать звонок по уроку временем урока (окно ±15 минут)? → A: Нет, позвонить по уроку можно всегда, и репетитору, и ученику.
- Q: Запрещать звонки с учеником в архиве? → A: Нет, не ограничивать.
- Q: Как выглядит подтверждение звонка? → A: Заголовок «Начать видеозвонок?»,
  под аватаром отдельной строкой имя собеседника; у звонка по уроку ниже блок
  «Звонок по уроку» (предмет, день, время); кнопки «Отмена» и «Позвонить»
  (правка макета, согласована пользователем).
- Q: Что происходит с карточкой ученика у репетитора после подтверждения звонка
  из неё? → A: Как и раньше, карточка закрывается после подтверждения; при отмене
  остаётся открытой.
- Q: Какие звонки показывает блок «Звонки по уроку» и когда он обновляется? →
  A: Все звонки, связанные с уроком, от любой стороны, новые сверху; список
  загружается при открытии окна урока и обновляется, когда меняется история
  звонков, пока окно открыто. Ошибка загрузки не показывается отдельно: блок
  просто не выводится.
- Q: Что видит звонящий, если сервер отклонил звонок по уроку? → A: Звонок
  не начинается, показывается ошибка как у существующих отказов звонка:
  «Урок не найден» (урок удалён или не принадлежит паре), «Звонок возможен
  только по уроку» (звонок ученика без урока).
- Q: Что значит «у ученика есть кабинет»? → A: К ученику привязана учётная
  запись ученика, то же условие, что у кнопки «Видеозвонок» в карточке ученика.

## Контекст (как сейчас)

- Репетитор может позвонить ученику только из окна карточки ученика
  (кнопка «Видеозвонок», видна, если у ученика есть кабинет и он не в архиве).
  В уроках кнопки звонка нет.
- У ученика в шапке кабинета («Кабинет ученика») есть общая кнопка «Позвонить»:
  звонит репетитору без связи с каким-либо уроком.
- У ученика карточки уроков в расписании не открывают попап урока.
- Звонок начинается сразу по нажатию, без подтверждения.
- Сервер запрещает звонки, если ученик в архиве.
- Записи звонков (`call_records`) не знают, к какому уроку относился звонок.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Репетитор звонит ученику из попапа урока (Priority: P1)

Репетитор открывает урок (из списка уроков или из сеточного расписания),
в окне просмотра урока есть кнопка «Позвонить». После подтверждения начинается
видеозвонок ученику этого урока, без перехода в раздел учеников.

**Why this priority**: Основной запрос: занятия проходят по видеосвязи,
и звонить естественно «из урока», а не из профиля ученика.

**Independent Test**: Открыть урок ученика с кабинетом: в окне урока есть
«Позвонить»; нажатие показывает подтверждение; после подтверждения окно урока
закрывается и начинается исходящий звонок этому ученику.

**Acceptance Scenarios**:

1. **Given** урок ученика с кабинетом, **When** репетитор открывает окно
   просмотра урока (из списка по дням, по неделям или из сеточного расписания),
   **Then** в действиях окна есть кнопка «Позвонить»
2. **Given** окно урока с кнопкой «Позвонить», **When** репетитор нажимает её,
   **Then** появляется подтверждение с именем ученика; звонок ещё не начат
3. **Given** подтверждение звонка, **When** репетитор подтверждает, **Then**
   окно урока закрывается и начинается исходящий видеозвонок ученику урока
4. **Given** подтверждение звонка, **When** репетитор отменяет его, **Then**
   звонок не начинается, окно урока остаётся открытым
5. **Given** урок в любом статусе и в любое время (прошедший, будущий,
   отменённый), **When** репетитор открывает окно урока ученика с кабинетом,
   **Then** кнопка «Позвонить» есть
6. **Given** ученик урока в архиве, **When** репетитор открывает окно урока,
   **Then** кнопка «Позвонить» есть и звонок проходит
7. **Given** пробный урок без привязанного ученика или урок ученика без кабинета,
   **When** репетитор открывает окно урока, **Then** кнопки «Позвонить» нет
8. **Given** список уроков, **When** репетитор смотрит карточки уроков,
   **Then** кнопки звонка на карточках нет (только в окне урока)
9. **Given** репетитор уже в звонке, **When** он подтверждает звонок из окна
   другого урока, **Then** второй звонок не начинается (как у существующей
   кнопки звонка)

### User Story 2 - Ученик звонит только из попапа урока, общей кнопки нет (Priority: P1)

В шапке кабинета ученика больше нет кнопки «Позвонить». Ученик нажимает
на карточку урока в расписании, открывается окно урока (предмет, дата и время,
длительность, статус) с кнопкой «Позвонить». После подтверждения звонок уходит
репетитору. Принимать входящие звонки ученик может, как и раньше, в любой момент.

**Why this priority**: Явное требование: ученик не должен звонить «одной
главной кнопкой», звонок привязан к уроку. Вместе с историей 1 это MVP.

**Independent Test**: Войти в кабинет ученика: в шапке нет кнопки звонка.
Нажать на карточку урока в расписании: открывается окно урока с «Позвонить»;
после подтверждения звонок уходит репетитору.

**Acceptance Scenarios**:

1. **Given** ученик в кабинете, **When** открывает любую страницу кабинета,
   **Then** в шапке нет кнопки «Позвонить»
2. **Given** расписание ученика, **When** ученик нажимает на карточку урока,
   **Then** открывается окно урока с данными урока и кнопкой «Позвонить»
3. **Given** окно урока, **When** ученик нажимает «Позвонить», **Then**
   появляется подтверждение с именем репетитора; после подтверждения окно
   закрывается и начинается исходящий видеозвонок репетитору; после отмены
   звонок не начинается
4. **Given** урок в любом статусе и в любое время, **When** ученик открывает
   окно урока, **Then** кнопка «Позвонить» есть
5. **Given** окно урока, **When** ученик закрывает его без звонка, **Then**
   возвращается к расписанию в том же состоянии (та же неделя)
6. **Given** ученик в кабинете, **When** репетитор звонит ему из карточки
   ученика, **Then** входящий звонок приходит и принимается как раньше

### User Story 3 - Подтверждение перед любым звонком (Priority: P1)

Чтобы случайно не позвонить, любой исходящий звонок начинается только после
подтверждения: из окна урока у обеих сторон и из карточки ученика у репетитора.

**Why this priority**: Явное требование пользователя; случайный звонок
беспокоит собеседника.

**Independent Test**: Нажать «Видеозвонок» в карточке ученика: появляется
подтверждение; отмена — звонка нет; подтверждение — звонок начат.

**Acceptance Scenarios**:

1. **Given** любая кнопка исходящего звонка, **When** пользователь нажимает её,
   **Then** показывается подтверждение с заголовком «Начать видеозвонок?»,
   аватаром и именем собеседника отдельной строкой под аватаром, кнопками
   «Позвонить» и «Отмена»; звонок до подтверждения не начинается
2. **Given** кнопка звонка в окне урока, **When** пользователь нажимает её,
   **Then** в подтверждении дополнительно есть блок «Звонок по уроку» с
   предметом, днём и временем урока; у звонка из карточки ученика блока нет
3. **Given** подтверждение открыто, **When** пользователь закрывает его
   (отмена, клик вне окна, Esc), **Then** звонок не начинается, окно, из
   которого звонили (урок или карточка ученика), остаётся открытым
4. **Given** подтверждение открыто, **When** пользователь быстро нажимает
   «Позвонить» дважды, **Then** начинается ровно один звонок
5. **Given** подтверждение звонка из карточки ученика, **When** репетитор
   подтверждает, **Then** карточка ученика закрывается и начинается исходящий
   видеозвонок ученику

---

### User Story 4 - Звонок привязан к уроку в данных и истории (Priority: P2)

Звонок, начатый из окна урока, сохраняется вместе с этим уроком. Получатель
во входящем звонке видит, по какому уроку звонят. В истории звонков у такого
звонка указан урок. В окне урока репетитор видит звонки по этому уроку.

**Why this priority**: «Звонок — атрибут урока» на уровне данных: видно,
состоялось ли занятие по видеосвязи и сколько длилось. Истории 1–3 работают
и без этого, поэтому P2.

**Independent Test**: Позвонить из окна урока, поговорить и завершить.
В истории звонков у записи виден урок; в окне урока есть этот звонок
с длительностью. Звонок из карточки ученика в истории без урока.

**Acceptance Scenarios**:

1. **Given** звонок начат из окна урока (любой стороной), **When** звонок
   завершён любым исходом (состоялся, пропущен, отклонён, отменён), **Then**
   запись звонка связана с этим уроком
2. **Given** входящий звонок по уроку, **When** у получателя показывается окно
   входящего звонка, **Then** в нём указан урок (предмет, дата и время)
3. **Given** запись звонка, связанная с уроком, **When** пользователь смотрит
   историю звонков, **Then** у записи указан урок (предмет, дата, время)
4. **Given** звонок из карточки ученика (без урока), **When** он завершён,
   **Then** запись звонка без урока, история показывает её как раньше
5. **Given** урок со звонками, **When** репетитор открывает окно урока,
   **Then** видит список звонков по уроку (исход и длительность);
   у урока без звонков блок не показывается
6. **Given** урок со связанными звонками удалён, **When** пользователь
   смотрит историю звонков, **Then** записи звонков остаются, но без урока

---

### Edge Cases

- Ученик подделывает запрос и звонит без урока или по чужому уроку: сервер
  отклоняет, звонок не начинается, запись звонка не создаётся
- Урок удалили, пока окно урока у ученика открыто: окно закрывается
  по обновлению в реальном времени; если звонок всё же отправлен, сервер
  отклоняет его с понятной ошибкой
- Урок завершился (статус «Проведён»), а звонок ещё идёт: звонок продолжается,
  запись остаётся связанной с уроком
- Звонок из окна урока, когда собеседник офлайн: запись «Пропущен» связана
  с уроком
- Ученика перевели в архив во время звонка: звонок продолжается
- Пока открыто подтверждение, пришёл входящий звонок: подтверждение
  закрывается, звонок не начинается, показывается входящий
- Окно урока и подтверждение на мобильной ширине: не ломают вёрстку,
  достаточная зона касания кнопок

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Кнопка «Позвонить» в шапке кабинета ученика MUST быть удалена.
  У ученика MUST NOT остаться способа начать звонок без привязки к уроку
- **FR-002**: Окно просмотра урока у репетитора MUST показывать кнопку
  «Позвонить», если у урока есть привязанный ученик с кабинетом. Статус урока,
  его время и архивность ученика на это не влияют
- **FR-003**: Карточки уроков в списках MUST NOT показывать кнопку звонка
- **FR-004**: Карточка урока в расписании ученика MUST открывать окно урока
  (предмет, дата и время, длительность, статус) с кнопкой «Позвонить»; кнопка
  доступна всегда
- **FR-005**: Любой исходящий звонок (из окна урока у обеих сторон, из карточки
  ученика у репетитора) MUST начинаться только после подтверждения. Окно
  подтверждения: заголовок «Начать видеозвонок?», аватар и под ним отдельной
  строкой имя собеседника, у звонка по уроку блок «Звонок по уроку» (предмет,
  день, время), кнопки «Отмена» и «Позвонить». Отмена или закрытие
  подтверждения MUST NOT начинать звонок
- **FR-006**: Подтверждённый звонок из окна урока закрывает окно урока;
  подтверждённый звонок из карточки ученика закрывает карточку ученика
- **FR-007**: Звонок из окна урока MUST передавать урок на сервер. Сервер
  MUST проверять, что урок существует и принадлежит паре репетитор–ученик
  этого звонка; иначе звонок отклоняется с ошибкой «Урок не найден»
- **FR-008**: Сервер MUST отклонять звонок от ученика без указания урока
  с ошибкой «Звонок возможен только по уроку»
- **FR-009**: Звонок репетитора без урока (из карточки ученика) MUST
  продолжать работать как сейчас (плюс подтверждение)
- **FR-010**: Сервер MUST NOT запрещать звонки из-за архивности ученика.
  Кнопка звонка в карточке ученика у репетитора MUST показываться и для
  ученика в архиве, если у него есть кабинет
- **FR-011**: Запись звонка MUST хранить ссылку на урок, если звонок начат
  из окна урока, для всех исходов звонка. При удалении урока записи звонков
  MUST сохраняться без ссылки на урок
- **FR-012**: Окно входящего звонка по уроку MUST показывать предмет, дату
  и время урока
- **FR-013**: История звонков MUST показывать урок (предмет, дата и время)
  у записей, связанных с уроком
- **FR-014**: Окно урока у репетитора MUST показывать звонки по этому уроку
  (направление, время, исход, длительность), если они есть: все звонки урока
  от любой стороны, новые сверху. Список обновляется, когда меняется история
  звонков, пока окно открыто; при ошибке загрузки блок не показывается
- **FR-015**: Защита от повторного нажатия, занятости и прочие правила
  существующих звонков MUST действовать и для звонков по уроку
- **FR-016**: Окно урока ученика и подтверждение звонка MUST корректно
  выглядеть на десктопе и на мобильной ширине

### Key Entities

- **Урок**: занятие репетитора с учеником (или пробное с потенциальным
  учеником). Для репетитора урок в ответе API дополнительно сообщает, есть ли
  у ученика кабинет (привязана учётная запись ученика; то же условие, что
  у кнопки «Видеозвонок» в карточке ученика).
- **Запись звонка**: существующая сущность; получает необязательную ссылку
  на урок.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Репетитор начинает звонок по уроку за 3 действия: открыть урок,
  «Позвонить», подтвердить (раньше: переход в учеников, поиск, открытие
  карточки, нажатие)
- **SC-002**: В кабинете ученика 0 мест, откуда можно позвонить вне урока
- **SC-003**: 0 звонков начинается одним случайным нажатием: каждый требует
  подтверждения
- **SC-004**: 100% звонков, начатых из урока, сохраняются со ссылкой на урок
- **SC-005**: 100% попыток звонка ученика без урока или по чужому уроку
  отклоняются сервером

## Assumptions

- Подтверждение распространяется на все кнопки исходящего звонка, включая
  существующую «Видеозвонок» в карточке ученика у репетитора.
- Снятие ограничения по архиву общее: и для звонков по уроку, и для звонков
  из карточки ученика.
- Компактная ячейка урока в сеточном расписании репетитора без кнопки: звонок
  доступен из окна урока, которое открывается по ячейке.
- Блок «Ближайшие уроки» на главной в рамки фичи не входит.
- Окно урока у ученика только для просмотра: без редактирования, оплаты,
  заметок и домашнего задания репетитора.
- Ученик видит урок во входящем звонке, только если звонок начат по уроку;
  звонки репетитора из карточки ученика выглядят как раньше.
- Список звонков в окне урока только у репетитора; ученик видит звонки
  по уроку в своей истории звонков.
