# Feature Specification: Гибкая ставка налога по периодам

**Feature Branch**: `027-tax-rate-periods`
**Created**: 2026-05-08
**Updated**: 2026-05-09
**Status**: Draft
**Input**: User description: "есть фича Ставка налога (%) - нужно сделать ее более гибкой, чтобы можно было указывать с какого периода должна быть применена какая ставка налога, соответственно периоды можно добавлять/удалять/изменять, все это должно влиять на пересчет налоговой статистики"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Включить расчёт налога и настроить периоды через попап (Priority: P1)

Репетитор открывает профиль и видит переключатель «Учитывать налог»,
по умолчанию выключенный. Пока тумблер выключен — никакой налоговой информации
в системе нет (карточка налога на статистике скрыта, настроек ставки нет).
Включив тумблер, репетитор видит кнопку «Настроить ставки», по клику
открывается модальное окно (попап), где он формирует свою налоговую историю:
добавляет периоды с указанием даты начала и ставки, редактирует и удаляет их.
После закрытия попапа с сохранением все его налоговые данные пересчитываются
по новой хронологии ставок.

**Why this priority**: Это контейнер фичи. Без тумблера и попапа пользователь
не может ни включить расчёт, ни настроить периоды — никакая другая часть
бессмысленна без этой.

**Independent Test**: Зайти в профиль нового пользователя, убедиться, что тумблер
выключен и налоговой карточки нигде нет. Включить тумблер, в попапе создать
два периода (например, 6% с 2024-01-01 и 4% с 2025-06-01), сохранить.
Открыть статистику — увидеть карточку налога. Вернуться в профиль, выключить
тумблер — карточка налога снова скрывается, периоды на сервере сохраняются.

**Acceptance Scenarios**:

1. **Given** новый репетитор зарегистрировался и открыл профиль,
   **When** он смотрит на блок «Налоги», **Then** видит выключенный тумблер
   «Учитывать налог», и нигде в системе (профиль, статистика) налоговая
   информация не отображается
2. **Given** репетитор включил тумблер «Учитывать налог», но ещё не настроил
   ни одного периода, **When** он пытается закрыть попап с сохранением,
   **Then** система требует добавить хотя бы один период перед сохранением
3. **Given** в попапе уже два периода (6% с 2024-01-01, 4% с 2025-06-01),
   **When** репетитор удаляет более поздний период и сохраняет, **Then**
   в попапе остаётся один период, попап закрывается, налог по всем уроком
   пересчитывается по 6% (с учётом ограничения «до самого раннего периода = 0%»)
4. **Given** в попапе есть период с датой начала 2025-06-01 и ставкой 4%,
   **When** репетитор меняет дату на 2025-07-01 и сохраняет, **Then**
   июньские оплаты пересчитываются по предыдущей ставке (6%) автоматически
5. **Given** в профиле тумблер был включён и было настроено 3 периода,
   **When** репетитор выключает тумблер и сохраняет профиль,
   **Then** карточка налога на статистике скрывается, кнопка «Настроить
   ставки» исчезает, но настроенные ранее периоды на сервере не удаляются
6. **Given** тумблер был выключен и снова включается, **When** попап
   открывается, **Then** в нём отображаются ранее сохранённые периоды
   (если такие были) или пустой список (для новых пользователей)
7. **Given** репетитор пытается удалить единственный оставшийся период
   при включённом тумблере, **When** он подтверждает удаление,
   **Then** система запрещает операцию и показывает сообщение, что должен
   остаться хотя бы один период (либо сначала нужно выключить тумблер)

### User Story 2 - Корректный пересчёт налога по дате оплаты с info-иконкой при смешанных ставках (Priority: P1)

Репетитор смотрит налоги на странице статистики за период, охватывающий
переход между ставками. Каждый урок облагается по той ставке, которая
действовала на **дату его оплаты** (а не на дату проведения урока), потому что
именно в момент поступления денег фиксируется доход и пробивается чек.
Если в выбранный фильтром диапазон попали оплаты под разными ставками,
карточка налога подписана нейтральным «Налоги» с info-иконкой; по клику /
наведению на иконку открывается всплывающая подсказка с разбивкой по каждой
применённой ставке (включая нулевую — для оплат до самого раннего периода).

**Why this priority**: Это пользовательская ценность ради которой делается фича.
Управление периодами без корректного пересчёта по дате оплаты — бесполезно.
Прозрачная разбивка по ставкам — обязательная часть UX, иначе сумма выглядит
как «магическое число».

**Independent Test**: Создать тестового пользователя с включённым тумблером
и двумя периодами; завести уроки с разными датами оплаты по обе стороны
границы между периодами и одну оплату с датой раньше самого раннего периода;
открыть статистику; проверить итоговую сумму и содержимое тултипа
по info-иконке.

**Acceptance Scenarios**:

1. **Given** периоды (6% с 2024-01-01, 4% с 2025-06-01) и есть один
   завершённый оплаченный урок на 1000 ₽ с датой оплаты 2025-05-15
   и один — с датой оплаты 2025-07-15,
   **When** репетитор смотрит статистику за май–июль 2025,
   **Then** сумма налога = 60 ₽ + 40 ₽ = 100 ₽
2. **Given** периоды (6% с 2024-01-01, 4% с 2025-06-01) и оплаченный урок
   на 1000 ₽, проведённый 2025-05-15, оплата по которому пришла 2025-07-01,
   **When** репетитор смотрит статистику, охватывающую дату оплаты,
   **Then** к этому уроку применяется ставка 4% (по дате оплаты), не 6%
3. **Given** в выбранный фильтр попадают оплаты только одной ставки,
   **When** карточка налога рендерится, **Then** в подписи указан
   конкретный процент, например «Налоги (4%)», info-иконка не показывается
4. **Given** в выбранный фильтр попадают оплаты под разными ставками
   (включая 0%-зону), **When** карточка налога рендерится,
   **Then** подпись — нейтральное «Налоги», рядом info-иконка;
   при наведении/клике открывается тултип со списком вида:
     - 6% × 50 000 ₽ = 3 000 ₽
     - 4% × 30 000 ₽ = 1 200 ₽
     - 0% × 5 000 ₽ = 0 ₽ (вне настроенных периодов)
5. **Given** оплата урока пришла раньше самого раннего настроенного периода
   (например, оплата 2023-09-01 при самом раннем периоде 2024-01-01),
   **When** считается налог, **Then** к этой оплате применяется ставка 0%
   (то есть налог = 0 ₽), а сама оплата помечается в тултипе строкой
   «вне настроенных периодов»
6. **Given** репетитор изменил ставку в одном из периодов с 6% на 7%,
   **When** он переходит на страницу статистики, **Then** все суммы налога
   за оплаты этого периода пересчитаны и обновлены без ручных действий

### User Story 3 - Видеть текущую активную ставку и историю переходов в попапе (Priority: P3)

В попапе настройки ставок репетитор видит свою налоговую историю в виде
хронологического списка с явным выделением: какой период сейчас активен,
какие были до него, какие назначены на будущее. Это помогает не путаться
при подаче декларации и не открывать редактирование ради информации.

**Why this priority**: Не блокирует основной флоу — список периодов уже
содержит эту информацию в неявном виде. Но повышает удобство и снижает
риск случайных правок.

**Independent Test**: Открыть попап с тремя настроенными периодами
(один в прошлом, один активен сейчас, один с датой начала в будущем),
проверить визуальное выделение активного и подпись «вступит в силу с …»
у будущего.

**Acceptance Scenarios**:

1. **Given** в попапе настроены три периода, **When** попап открывается,
   **Then** периоды отображаются в виде хронологического списка
   с явным выделением текущего активного периода
2. **Given** есть период с будущей датой начала, **When** список рендерится,
   **Then** этот период визуально отделён от уже наступивших и подписан
   как «вступит в силу с …»

---

### Edge Cases

- **Тумблер выключен**: налоговая карточка на статистике скрыта полностью;
  в профиле кнопка «Настроить ставки» не отображается; ранее сохранённые
  периоды остаются на сервере, но не используются для расчёта.
- **Тумблер ON, ноль периодов**: запрещено сохранение в таком состоянии —
  попап требует добавить минимум один период; либо тумблер автоматически
  откатывается в OFF.
- **Оплата урока до даты начала самого раннего периода**: ставка = 0%,
  налог = 0 ₽; оплата отражается отдельной строкой в тултипе info-иконки.
- **Урок без даты оплаты (не оплачен)**: исключён из расчёта налога
  (как и из расчёта заработка) — текущая логика сохраняется.
- **Несколько периодов с одной датой начала**: запрещено — система отклоняет
  сохранение, если у пользователя получаются два периода с одинаковой
  датой начала.
- **Изменение даты начала так, что она совпадает с датой другого периода**:
  операция отклоняется до сохранения с понятным сообщением.
- **Удаление самого раннего периода при включённом тумблере**: оставшийся
  самый ранний период становится новой границей; всё, что раньше его —
  попадает в зону 0%.
- **Период с датой начала в будущем**: разрешён (планирование смены режима);
  к прошлым оплатам не применяется; помечается в попапе соответствующей
  подписью.
- **Ставка 0% в одном из периодов**: разрешена (например, налоговые каникулы);
  попадающие в неё оплаты дают налог 0 ₽ и в тултипе показываются
  отдельной строкой «0% × … ₽ = 0 ₽».
- **Дробные ставки** (например, 6.5%): разрешены; итоговая сумма налога
  округляется до целых рублей по каждой оплате.
- **Большой диапазон фильтра, охватывающий 5+ периодов**: статистика
  считается корректно при типичном объёме истории (до ~10 периодов
  на пользователя); тултип содержит все попавшие ставки построчно.

## Requirements *(mandatory)*

### Functional Requirements

#### Тумблер «Учитывать налог»

- **FR-001**: В профиле пользователя MUST присутствовать переключатель
  «Учитывать налог» с двумя состояниями (включён / выключен).
- **FR-002**: Для всех новых пользователей переключатель MUST быть
  по умолчанию выключен.
- **FR-003**: Когда переключатель выключен, система MUST скрывать карточку
  налога на странице статистики, скрывать кнопку «Настроить ставки»
  в профиле и не выполнять расчёт налога ни в одном из агрегатов.
- **FR-004**: Когда переключатель включён, система MUST показывать кнопку
  «Настроить ставки» в профиле, налоговую карточку на статистике
  и выполнять расчёт по настроенным периодам.
- **FR-005**: Переключатель не может быть сохранён во включённом состоянии,
  если у пользователя нет ни одного настроенного периода — UI MUST
  требовать добавить хотя бы один период перед сохранением.
- **FR-006**: Выключение переключателя MUST сохранять ранее настроенные
  периоды на сервере; повторное включение MUST показывать тот же список
  без потерь.

#### Попап управления периодами

- **FR-007**: Управление периодами MUST происходить в модальном окне
  (попапе), открываемом по кнопке в профиле; на странице профиля
  не должно быть инлайн-редактирования периодов.
- **FR-008**: Попап MUST позволять: просмотр всех периодов в хронологическом
  порядке; добавление нового периода с указанием даты начала и ставки;
  редактирование даты и/или ставки существующего периода; удаление периода.
- **FR-009**: Сохранение изменений в попапе MUST быть атомарным:
  все правки применяются разом по нажатию «Сохранить»; отмена
  (закрытие без сохранения) откатывает локальные правки.
- **FR-010**: Невозможно удалить последний оставшийся период при
  включённом переключателе — операция запрещается с понятным сообщением.

#### Структура и валидация периодов

- **FR-011**: Каждый период MUST состоять из двух атрибутов: дата начала
  действия и ставка налога в процентах.
- **FR-012**: Ставка налога MUST принимать значения от 0 до 100 включительно
  с точностью до одного десятичного знака.
- **FR-013**: Дата начала периода MUST быть уникальной в рамках одного
  пользователя.
- **FR-014**: Все изменения в попапе MUST валидироваться на сервере;
  попытки сохранить дубликаты дат, ставки вне диапазона, удалить
  последний период или включить тумблер без периодов MUST отклоняться
  с русскоязычным сообщением.

#### Расчёт налога

- **FR-015**: Применимая к оплате ставка MUST определяться по дате оплаты
  урока (а не по дате его проведения): выбирается период, чья дата начала
  ≤ дата оплаты и нет более позднего периода с датой начала ≤ дата оплаты.
- **FR-016**: Если дата оплаты урока раньше самого раннего настроенного
  периода, к этой оплате MUST применяться ставка 0% (налог по этой оплате
  равен 0 ₽); период «не продлевается» в прошлое.
- **FR-017**: Итоговая сумма налога на странице статистики MUST
  рассчитываться как сумма по каждой оплаченной оплате
  (заработок × применимая ставка / 100, округление до целых рублей).
- **FR-018**: Изменение, добавление или удаление периода, а также
  переключение тумблера MUST вступать в силу при следующем запросе
  данных статистики без необходимости вручную перезагружать страницу.

#### Карточка налога и info-иконка

- **FR-019**: Если в выбранный фильтром интервал попадают оплаты только
  одной применимой ставки, карточка налога MUST содержать эту ставку
  в подписи (например, «Налоги (6%)»); info-иконка не отображается.
- **FR-020**: Если в выбранный фильтром интервал попадают оплаты под
  несколькими применимыми ставками (включая 0%-зону), карточка налога
  MUST подписываться нейтрально «Налоги» (без процента в подписи),
  рядом с подписью MUST отображаться info-иконка.
- **FR-021**: При наведении или клике на info-иконку MUST открываться
  всплывающая подсказка с разбивкой: для каждой применённой в выбранном
  интервале ставки — строка вида «X% × Y ₽ = Z ₽»; для оплат вне
  настроенных периодов — отдельная строка с пометкой «вне настроенных
  периодов».

#### Миграция существующих пользователей

- **FR-022**: При раскатке фичи существующие пользователи, у которых
  ставка явно отличается от исторического дефолта 6%, MUST получить
  включённый переключатель и один начальный период с их ставкой;
  дата начала этого периода MUST быть гарантированно раньше любых
  их оплат (например, дата регистрации).
- **FR-023**: Существующие пользователи с дефолтной ставкой 6% MUST
  получить выключенный переключатель и пустой список периодов
  (как новые пользователи); разница исчезает после первого включения
  тумблера и настройки.

### Key Entities

- **Налоговый период (TaxRatePeriod)**: принадлежит пользователю, имеет
  дату начала действия и ставку налога в процентах. Список периодов
  одного пользователя образует хронологическую цепочку без пересечений:
  каждый период действует от своей даты начала до начала следующего
  периода. Время до самого раннего периода — зона 0%.
- **Пользователь (User)**: вместо одиночного атрибута «ставка налога»
  владеет: (а) переключателем «Учитывать налог»; (б) списком налоговых
  периодов (может быть пустым, если переключатель выключен).

### Assumptions

- Принадлежность оплаты к периоду определяется датой оплаты урока,
  а не датой его проведения — это совпадает с принципом «налог
  фиксируется в момент пробития чека / поступления денег».
- Расчёт ведётся только по уроком, у которых есть дата оплаты
  (то есть только по фактически оплаченным урокам); сценарий
  «оплачен, но без даты оплаты» в текущей модели данных невозможен.
- Время до самого раннего настроенного периода трактуется как зона 0%,
  чтобы не навязывать пользователю «исторические» налоги, которые он
  не настраивал — пользователь явно решает, с какой даты у него начинается
  налогообложение.
- Тумблер по умолчанию выключен для всех новых пользователей; для
  существующих пользователей применяется миграция по эвристике
  «отличается ли сохранённая ставка от 6% (исторический дефолт)»;
  это разумный компромисс: те, кто явно настраивал, не теряют
  расчёт, остальные получают чистый старт согласно новой модели.
- Управление периодами — только через попап; на странице профиля
  отображается лишь тумблер и кнопка для открытия попапа.
- Для тултипа info-иконки достаточно строкового списка ставок
  без графической диаграммы; список содержит и нулевую ставку
  для оплат вне настроенных периодов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новый репетитор, никогда не настраивавший налоги, не видит
  никакой налоговой информации нигде в системе по умолчанию (профиль,
  статистика, экспорт) — пока сам не включит тумблер.
- **SC-002**: Сумма налога на странице статистики совпадает с ручным
  расчётом «по каждой оплате × ставка соответствующего периода / 100,
  округление до рублей, суммирование» для 100% сценариев на тестовых
  данных, включающих переходы между ставками и оплаты до самого раннего
  периода (зона 0%).
- **SC-003**: Когда в выбранный диапазон попадают оплаты разных ставок,
  тултип info-иконки даёт пользователю исчерпывающую разбивку
  (по ставкам и суммам), без необходимости делать ручной расчёт
  снаружи системы.
- **SC-004**: Все ошибочные операции (дубликаты дат, ставка вне диапазона,
  удаление последнего периода, включение тумблера без периодов)
  отклоняются с понятным русскоязычным сообщением в 100% случаев.
- **SC-005**: Время на полную настройку нового сценария (включение тумблера
  + добавление трёх периодов + сохранение) не превышает 60 секунд
  для пользователя, открывшего профиль впервые.
- **SC-006**: Включение/выключение тумблера и любые правки в попапе
  отражаются на дашборде статистики при следующем переходе на страницу
  без необходимости вручную обновлять браузер.
