# Contract: REST для push-подписок и настроек — 039

## Ученик (новое): `/api/student-push`

Изолированная подсистема (backend.md): `authenticateStudent`, токен преподавателя отвергается (401), регрессионные тесты cross-role обязательны. Ключ VAPID — существующий публичный `GET /api/push/vapid-key`.

### `POST /api/student-push/subscribe`

Request (как у преподавателя):

```json
{ "subscription": { "endpoint": "https://…", "keys": { "p256dh": "…", "auth": "…" } }, "deviceName": "iPhone" }
```

| Код | Когда | Тело |
|-----|-------|------|
| 201 | создана | `{ id, endpoint, deviceName, createdAt }` |
| 200 | эндпоинт уже принадлежит этому ученику (upsert ключей) | то же |
| 200 | эндпоинт принадлежит другому владельцу, но запрос несёт его ключи `p256dh` и `auth` — запись перепривязана к этому ученику | то же |
| 400 | невалидные данные (общий валидатор) | `{ error: "Некорректные данные подписки" }` / `{ error: "Название устройства слишком длинное" }` |
| 403 | эндпоинт принадлежит другому владельцу (преподавателю или другому ученику), а ключи не совпадают с сохранёнными | `{ error: "Подписка принадлежит другому пользователю" }` |
| 401 | нет/чужой токен | |

Запись: `channel = WEB_PUSH`, `studentUserId = req.studentUser.studentUserId`, `userId = null`.

#### Перепривязка подписки держателем браузера

Браузер хранит одну подписку на origin и отдаёт её любой странице приложения, поэтому после сессии, закончившейся без выхода (истёк токен, вход ученика поверх преподавателя), в браузере остаётся подписка прежнего аккаунта. Кабинет ученика при входе (`syncSubscriptionFx`) и кнопка «Включить» (`enableFx`) отправляют именно её — `getSubscription()` возвращает существующую. Раньше это давало 403: ученик не мог включить уведомления на своём устройстве, а прежний владелец продолжал получать на это устройство свои push (напоминания и звонки преподавателя — на устройство, которым пользуется ученик).

Правило: если запрос несёт тот же `endpoint` **и** те же `keys.p256dh` и `keys.auth`, что сохранены в записи, запись переходит к текущему ученику (`userId = null`, `studentUserId = текущий`, тот же `id`), прежний владелец перестаёт получать push на это устройство.

Почему это безопасно:

- `endpoint` — URL push-сервиса, но не секрет в строгом смысле: он может утечь (логи, `GET /api/push/subscriptions` отдаёт его владельцу). Поэтому одного `endpoint` недостаточно — без ключей остаётся 403, запись не меняется.
- `auth` — 16 случайных байт, которые браузер генерирует при создании подписки; вместе с `p256dh` они есть только в этом браузере (`PushSubscription.toJSON()`) и в таблице `push_subscriptions`. Ни один API их не возвращает. Знать все три значения может только тот, кто держит этот браузер (или имеет доступ к БД).
- Держатель браузера и так видит все уведомления, приходящие на устройство; перепривязка не даёт ему ничего сверх этого, а только переносит доставку на текущий аккаунт — прежний владелец перестаёт получать push туда, где теперь работает другой человек.
- Подобрать ключи нельзя: сравнение `timingSafeEqual`, расхождение в любом ключе → 403. Отправлять push на чужой endpoint напрямую нельзя без приватного VAPID-ключа сервера.
- Перепривязка не трогает другие устройства прежнего владельца и не даёт доступа к его данным.

Клиенту ничего делать не нужно: он уже отправляет подписку браузера с ключами. То же правило действует на эндпоинте преподавателя (`POST /api/push/subscribe`, ниже).

#### Не больше 10 устройств на владельца

Push о звонке уходит на все устройства получателя одновременно, поэтому число подписок одного владельца (преподавателя или ученика) ограничено: `MAX_PUSH_SUBSCRIPTIONS_PER_OWNER = 10` (`services/pushSubscription`). Правило одно для обоих маршрутов `subscribe`:

- После записи (создание, обновление ключей или перепривязка) у владельца остаются 10 подписок с самым поздним `createdAt`, остальные удаляются. Только что записанная подписка не удаляется никогда.
- Повторная отправка подписки обновляет `createdAt` на текущее время (в ответе — новое значение): клиент отправляет подписку браузера при каждом входе (`syncSubscriptionFx`), так что удаляются устройства, которые дольше всех не регистрировались, а не первые добавленные.
- Выборка устройств для push о звонке (`notifyIncomingCall`, `notifyCallClosed`) тоже берёт не больше 10 самых свежих — на случай строк, записанных до ограничения.
- Удалённое устройство при следующем входе снова отправит подписку и вернётся в число 10 (ответ 201).

Ответы маршрутов не меняются.

### `DELETE /api/student-push/unsubscribe`

Body `{ "endpoint": "…" }`. 200 `{ message: "Подписка удалена" }`; 400 без endpoint; 404 `{ error: "Подписка не найдена" }`, если эндпоинт не этого ученика.

## Преподаватель (существующее, изменения)

- `POST /api/push/subscribe`: запись получает `channel = WEB_PUSH`, `userId = req.user.userId`, `studentUserId = null`.

| Код | Когда | Тело |
|-----|-------|------|
| 201 | создана | `{ id, endpoint, deviceName, createdAt }` |
| 200 | эндпоинт уже принадлежит этому преподавателю (upsert ключей) | то же |
| 200 | эндпоинт принадлежит другому владельцу (ученику или другому преподавателю), но запрос несёт его ключи `p256dh` и `auth` — запись перепривязана к этому преподавателю (то же правило и обоснование, что у ученика, «Перепривязка подписки держателем браузера») | то же |
| 400 | невалидные данные | как у ученика |
| 403 | эндпоинт принадлежит другому владельцу, а ключи не совпадают с сохранёнными | `{ error: "Подписка принадлежит другому пользователю" }` |

- Клиент преподавателя один раз за сессию преподавателя повторно отправляет существующую подписку браузера (`notificationsModel.syncSubscriptionFx`), если разрешение выдано и включены напоминания или уведомления о звонках: браузер мог остаться с подпиской ученика или другого преподавателя (сессия закончилась без выхода), тогда `$isPushSubscribed` был бы `true`, а push до этого преподавателя не доходили бы. Ошибка запроса показывает устройство неподписанным (`$isPushSubscribed = false`), переключатель «Уведомления о входящих звонках» тогда предлагает подписаться заново.
- `GET /api/push/subscriptions`, `DELETE /api/push/unsubscribe` — без изменений (фильтр по `userId`).
- `GET /api/reminder-settings` → `{ enabled, intervals, muteWhenInLesson, callNotificationsEnabled }`.
- `PUT /api/reminder-settings` принимает `callNotificationsEnabled?: boolean`; не boolean → 400 `{ error: "Некорректное значение настройки уведомлений о звонках" }`.
