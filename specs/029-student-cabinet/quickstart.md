# Quickstart — Личный кабинет ученика (MVP)

**Feature**: 029-student-cabinet
**Цель документа**: пройти фичу руками после её реализации, чтобы убедиться, что все user stories из [spec.md](./spec.md) выполнены и edge cases отработаны.

---

## 0. Предусловия

```bash
# Backend (отдельный терминал)
cd backend
npm run db:migrate           # применит миграцию 029_student_cabinet
npm run db:generate          # обновит Prisma Client
npm run dev                  # на порту 3001

# Frontend (отдельный терминал)
cd frontend
npm start                    # дев-сервер на 3000

# В .env (backend) добавлено:
#   STUDENT_JWT_SECRET=...   (длинная случайная строка, отличная от JWT_SECRET и ADMIN_JWT_SECRET)
```

В БД должно быть:
- хотя бы один аккаунт-преподаватель (`User`) с подтверждённым email
- у этого преподавателя — хотя бы один **не архивированный** ученик (`Student`) с уроками на этой и следующей неделях

## 1. P1 — Регистрация ученика по приглашению

### 1.1 Преподаватель создаёт ссылку

1. Войти под преподавателем (на `/login`, тумблер в положении "преподаватель")
2. Перейти в раздел "Ученики" → открыть карточку существующего ученика
3. В карточке должна появиться **новая секция "Личный кабинет ученика"** со статусом **"не выдано"** и кнопкой **"Создать ссылку-приглашение"**
4. Нажать кнопку → появляется блок с полным URL (`https://<host>/student-invite/<token>`) и кнопкой "Скопировать"
5. Скопировать URL в буфер обмена

✅ **Ожидание**: статус карточки переключился на "ожидает регистрации" (с указанием даты создания и срока действия). Кнопка "Создать ссылку" заменена на "Создать новую" + "Отозвать".

### 1.2 Ученик регистрируется

1. Открыть скопированный URL в **приватной вкладке** (или другом браузере) — без активной сессии
2. Должна открыться страница регистрации с:
   - Приветствием "<ФИО ученика из карточки>" (опционально, чтобы убедиться, что ссылка на правильного ученика)
   - Полями: ФИО, Email, Пароль, Подтверждение пароля
3. Заполнить форму валидными значениями (ФИО любое — может отличаться от того, что в карточке; email — реальный, на который придёт код)
4. Нажать **"Зарегистрироваться"**

✅ **Ожидание**:
- Аккаунт создан
- Ученик автоматически авторизован (на странице — кабинет ученика)
- На введённый email пришло письмо с 6-значным кодом верификации
- В UI кабинета — баннер "Подтвердите email" с полем ввода кода и кнопкой "Отправить заново" (cooldown 60 с)

### 1.3 Подтверждение email

1. Ввести код из письма → нажать "Подтвердить"

✅ **Ожидание**: баннер исчез, в "Настройках" email отображается без статуса "не подтверждён".

### 1.4 Преподаватель видит, что ученик зарегистрировался

1. В сессии преподавателя обновить страницу карточки ученика
2. В секции "Личный кабинет ученика" статус переключился на **"Ученик зарегистрирован"** с датой регистрации и email, под которым ученик зарегистрировался
3. Кнопок "Создать ссылку" / "Создать новую" / "Отозвать" больше нет

✅ **Ожидание**: индикатор регистрации виден явно (бейдж/иконка), повторная генерация ссылки невозможна.

## 2. P2 — Расписание ученика

### 2.1 Просмотр своих уроков

1. В сессии ученика → раздел "Расписание"
2. Должен появиться **понедельный календарь** (ПН–ВС) с уроками этого ученика
3. Кликнуть на карточку любого урока

✅ **Ожидание**:
- Карточка показывает: предмет, дата, время начала, длительность/время окончания, статус
- **Никаких** кнопок: "Редактировать", "Удалить", "Отметить оплаченным", "Перенести", "+ Урок" — ничего из tutor-функций
- Никаких полей про оплату, заметки преподавателя, домашку
- Других учеников этого преподавателя на сетке нет

### 2.2 Переключение недели

1. Нажать "← Предыдущая неделя", "Следующая неделя →", "Сегодня"

✅ **Ожидание**: сетка обновляется, остаются видны только уроки этого ученика.

### 2.3 Пустая неделя

1. Перейти на неделю, на которой у ученика нет уроков (например, далеко в будущем)

✅ **Ожидание**: сетка отображается, карточек нет, текст "На этой неделе уроков нет".

### 2.4 Realtime-обновления расписания (R-09)

1. Открыть кабинет ученика в одной вкладке (раздел "Расписание")
2. В другой вкладке (или другом браузере) под преподавателем — добавить новый урок этому ученику на текущей неделе
3. **Не обновляя** страницу ученика — посмотреть на сетку

✅ **Ожидание**: новый урок появляется в расписании ученика в реальном времени (через WS-сообщение `lesson_created`).

4. Под преподавателем — изменить статус существующего урока (например, отметить как завершённый)

✅ **Ожидание**: статус урока в кабинете ученика обновляется без перезагрузки.

5. Под преподавателем — удалить урок ученика

✅ **Ожидание**: карточка пропадает из расписания ученика мгновенно.

6. Cross-role security: попытаться открыть `wss://<host>/ws/student?token=<tutorToken>` (например, через DevTools)

✅ **Ожидание**: соединение закрывается с кодом 1008 ("Authentication failed"). И обратно — `wss://<host>/ws?token=<studentToken>` тоже отклоняется.

### 2.5 Изоляция от tutor-разделов

1. Скопировать URL `http://localhost:3000/students` (репетиторская страница) и открыть в той же вкладке ученика

✅ **Ожидание**: либо редирект на разрешённый раздел кабинета, либо страница "Доступ запрещён" — НЕ tutor UI.

2. На уровне API — попробовать (например, через DevTools fetch):
   ```js
   await fetch('/api/students', { headers: { Authorization: `Bearer ${studentToken}` } })
   ```

✅ **Ожидание**: 401 Unauthorized.

3. Обратно — tutor JWT не должен работать для student-эндпоинтов:
   ```js
   await fetch('/api/student-cabinet/lessons', { headers: { Authorization: `Bearer ${tutorToken}` } })
   ```

✅ **Ожидание**: 401 Unauthorized.

## 3. P3 — Настройки

1. В сессии ученика → раздел "Настройки"

✅ **Ожидание**:
- ФИО ученика (введённое при регистрации) — отображается, поле read-only
- Email ученика — отображается, со статусом "подтверждён"
- ФИО преподавателя — отображается, read-only
- Никаких кнопок "Сохранить", "Изменить", "Сменить пароль" — read-only

## 4. Edge cases — обязательные проверки

### 4.1 Повторное использование ссылки

1. Закрыть сессию ученика, выйти
2. Открыть тот же `/student-invite/<token>` ещё раз

✅ **Ожидание**: страница "Ссылка уже использована" + предложение обратиться к преподавателю.

### 4.2 Невалидный токен

1. Открыть `/student-invite/000000000000000000000000000000`

✅ **Ожидание**: страница "Ссылка недействительна" (тот же текст, что для использованной — пользователь не должен различать причины, FR-016).

### 4.3 Перевыпуск ссылки до регистрации

(Подготовка: создать второго ученика и выдать ему ссылку, пока он ещё не зарегистрировался.)

1. В карточке этого второго ученика нажать "Создать новую ссылку"
2. Должна вернуться **новая** URL
3. Открыть **старую** URL в приватной вкладке

✅ **Ожидание**: "Ссылка недействительна".

4. Открыть **новую** URL → пройти регистрацию

✅ **Ожидание**: успешная регистрация.

### 4.4 Удаление карточки после регистрации (FR-020a)

1. В сессии преподавателя удалить (или архивировать) карточку зарегистрированного ученика
2. В сессии ученика обновить раздел "Расписание"

✅ **Ожидание**:
- Ученик может войти и видит свой кабинет
- В "Расписании" — пусто, "На этой неделе уроков нет" на всех неделях (уроки удалены каскадом)
- В "Настройках" — ФИО и email ученика по-прежнему отображаются; на месте преподавателя — текст "Связь с преподавателем прекращена"

### 4.5 Архивированный ученик (R-14)

1. Создать карточку ученика, **до** генерации приглашения архивировать её
2. В карточке нажать "Создать ссылку-приглашение"

✅ **Ожидание**: кнопка либо скрыта, либо при нажатии возвращает ошибку "Архивированному ученику нельзя выдать приглашение" (или 409 от API).

### 4.6 Email коллизии (FR-011a, R-07)

1. Создать ученика A, выдать ему ссылку, зарегистрировать с email `kid@example.com`
2. Создать ученика B (другая карточка), выдать ему ссылку, попытаться зарегистрировать с тем же `kid@example.com`

✅ **Ожидание**: ошибка "Этот email уже используется в другом аккаунте ученика. Используйте другой email или обратитесь к преподавателю."

3. Зарегистрировать аккаунт-преподавателя с email `kid@example.com` (через стандартную регистрацию tutor)

✅ **Ожидание**: успех. Один и тот же email может одновременно работать как tutor и как student — разные подсистемы.

### 4.7 Тумблер на /login (FR-019, FR-019a)

1. На `/login` — тумблер "Войти как: преподаватель / ученик"
2. По умолчанию — "преподаватель", кнопка "Войти" логинит в tutor-кабинет
3. Переключить на "ученик", ввести email/пароль ученика → попасть в кабинет ученика
4. Попытка ввести tutor email/пароль с тумблером "ученик"

✅ **Ожидание**: ошибка "Неверный email или пароль" (без подсказок про другую роль).

### 4.8 Tutor открывает invitation-ссылку (AC-8 в US1)

1. Под сессией tutor открыть `/student-invite/<свежий-token>`

✅ **Ожидание**: предупреждение "Вы вошли как преподаватель. Чтобы зарегистрировать ученика, выйдите из текущей сессии." Сама форма регистрации до выхода не показывается (или не активна).
