# Спецификация: Админ-панель

**Бранч**: `025-admin-panel` | **Дата**: 2026-03-30

## Контекст

Приложение для управления репетиторством. Сейчас все пользователи равноправны, нет системы ролей. Нужна отдельная админ-панель для системного администрирования. Первая фича админки — управление бэкапами БД (уже реализована на бэкенде).

## Требования

### Аутентификация админа
- Креды задаются через переменные окружения: `ADMIN_EMAIL`, `ADMIN_PASSWORD`
- Отдельный эндпоинт логина: `POST /api/admin/login`
- Отдельный JWT с пометкой `isAdmin: true`
- Не зависит от таблицы User — админ не является пользователем приложения
- Отдельный middleware `authenticateAdmin` для защиты админских роутов

### Админ-панель (Frontend)
- Отдельная страница `/admin` с формой логина
- После авторизации — дашборд с разделами
- Токен админа хранится отдельно от пользовательского (localStorage ключ `adminToken`)
- Отдельный axios instance для админ-запросов

### Раздел: Бэкапы БД (первая фича)
- Просмотр текущих настроек бэкапов (частота, лимит хранилища)
- Редактирование настроек
- Список существующих бэкапов (имя, размер, дата)
- Кнопка «Создать бэкап вручную»
- Общий занятый объём

### Раздел: Обзор системы
- Количество пользователей
- Количество уроков
- Количество студентов
- Uptime сервера (время с момента запуска)

## Вне скоупа
- Управление пользователями (блокировка, удаление)
- Просмотр данных конкретных пользователей
- Редактирование контента (новости и т.д.)
- Мониторинг ошибок / логи
