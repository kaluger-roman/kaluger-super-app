# Quickstart: Полноэкранный режим в звонке

**Feature**: `039-call-fullscreen` | **Plan**: [plan.md](./plan.md)

Только фронтенд: миграций, новых переменных окружения и зависимостей нет.
Все команды — на машине `home` в worktree
`~/kaluger-super-app/.claude/worktrees/call-fullscreen-tmp`
(`ssh home 'source ~/.nvm/nvm.sh; cd <worktree> && …'`).

## 1. Запуск

```bash
cd backend && npm run dev        # API + WebSocket (сигналинг звонка)
cd frontend && npm start         # SPA
```

Для звонка нужны две стороны: репетитор (обычный вход) и ученик с доступом
в кабинет (приглашение из карточки ученика), в двух браузерах или окне
инкогнито. Демонстрацию экрана включает ученик кнопкой «Демонстрация
экрана» на панели звонка (на компьютере; на телефоне браузеры её не дают).

## 3. Ручная проверка — US1 (P1), окно 1440×900

1. Начать звонок, ученик включает демонстрацию экрана. В правом верхнем
   углу плитки собеседника — кнопка «Во весь экран»; остальной вид как
   раньше (FR-013).
2. Нажать «Во весь экран»: демонстрация на всю ширину окна (1440 px;
   SC-001), нет шапки, отступов и своего превью. Сверху имя, таймер,
   «Демонстрация экрана» и «Свернуть», снизу кнопки звонка и группа масштаба.
3. Не двигать мышь 3 с: панели и курсор над видео исчезают. Пошевелить —
   появляются. Держать курсор над нижней панелью дольше 3 с — не исчезает.
4. Щёлкнуть «Выключить микрофон» и увести курсор с панели: через 3 с
   панель прячется (фокус после щелчка не держит её — Clarification 4),
   микрофон выключен, режим включён (FR-005).
5. Tab при скрытой панели: панель появляется, фокус на кнопке, пока фокус
   с клавиатуры на панели — не прячется.
6. Esc → обычный вид, звонок, микрофон, камера и демонстрация
   не изменились (FR-006). Двойной щелчок по видео → режим; ещё раз → выход.
   Двойной щелчок по «Во весь экран» / «Свернуть» режим дважды не переключает.
7. Ученик останавливает демонстрацию: режим остаётся, на всё окно его
   камера (кадр заполняет окно) или аватар, группы масштаба нет.
8. Начать новый звонок после завершения в режиме — обычный вид (FR-007).
9. Во время «Соединение…» (сразу после принятия вызова) «Во весь экран»
   доступна, баннер виден под верхней панелью (Clarification 1, FR-008).

## 4. Ручная проверка — US2 (P2)

На компьютере, демонстрация, режим включён:

1. Колесо над видео — масштаб меняется вокруг курсора, подпись процента
   меняется, страница браузера не масштабируется (в т. ч. щипок тачпада).
2. «+» трижды: 150 → 200 → 250 %; «Исходный размер» появляется при > 100 %.
   После колеса на ~170 % «+» даёт 200 %, «−» — 150 % (Clarification 5).
3. Перетащить мышью: картинка двигается, но край не уходит внутрь окна
   (чёрного поля у края нет); при 4× дойти до каждого угла.
4. «−» до упора или «Исходный размер» → 100 %, кнопка сброса исчезает.
5. Увеличить, «Свернуть», снова «Во весь экран» → 100 % (FR-010).
   Увеличить, ученик останавливает демонстрацию и начинает снова → 100 %.
6. Сузить окно браузера при 3× — картинка остаётся в границах.

На iPhone (Safari), 375×812 (SC-002, SC-004, SC-005):

1. Портрет: демонстрация 16:9 во всю ширину без боковых отступов;
   вкладки и адресная строка Safari остаются (нет системного fullscreen).
2. Двойное касание по видео включает / выключает режим.
3. Щипок увеличивает вокруг пальцев до 4×, страница не масштабируется;
   одним пальцем картинка двигается в границах.
4. Касание показывает панель, через 3 с без касаний она прячется;
   одиночное касание видимую панель не прячет.
5. Повернуть в альбомную (812×375): демонстрация на всю высоту, режим
   включён, масштаб 100 %.
6. Свернуть Safari и вернуться: если видео встало, «Видео на паузе.
   Нажмите, чтобы продолжить» видна в режиме; касание по ней возобновляет
   видео, не переключает режим и не показывает панель.

## 5. Что не должно измениться

- Обычный вид звонка, экраны исходящего и входящего вызова.
- Собеседник никак не узнаёт о режиме и масштабе (ничего не уходит
  по сигналингу — проверить, что в devtools WebSocket нет новых сообщений).
- Бэкенд: ни одного изменённого файла в `backend/`.
