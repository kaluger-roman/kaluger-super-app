# Research: 006-tax-statistics

## R1: Серверный расчёт налога в существующем эндпоинте

**Decision**: Добавить расчёт `taxAmount` прямо в контроллер `getStatistics.ts`,
рядом с существующим расчётом `earnings`.

**Rationale**: Контроллер уже выполняет 9+ запросов через `Promise.all`.
Добавление одного `prisma.user.findUnique` для получения `taxRate` — минимальная
нагрузка. Формула `Math.round(earnings * taxRate / 100)` тривиальна и не требует
выделения в отдельный service.

**Alternatives considered**:
- Отдельный эндпоинт `/statistics/tax` — отклонён: лишний HTTP-запрос, данные
  уже есть в основном ответе
- Расчёт на клиенте — отклонён по требованию заказчика (FR-008)
- Вынос в service — отклонён: формула в одну строку, service добавит сложности
  без пользы (принцип VII — Simplicity)

## R2: Хранение ставки налога

**Decision**: Поле `taxRate Float @default(6.0)` в модели User (Prisma).

**Rationale**: Ставка — атрибут пользователя, не урока. Один Float с дефолтом
покрывает все сценарии (новые пользователи, миграция существующих). Prisma миграция
автоматически проставит 6.0 для всех существующих записей.

**Alternatives considered**:
- Отдельная таблица Settings — отклонена: over-engineering для одного поля
- JSON-поле с настройками — отклонено: потеря type safety и невозможность
  использовать значение напрямую в запросах

## R3: Валидация ставки налога

**Decision**: Валидация 0 ≤ taxRate ≤ 100 на бэкенде в контроллере `updateProfile`.
На фронте — MUI TextField type="number" с `inputProps={{ min: 0, max: 100, step: 0.1 }}`.

**Rationale**: Бэкенд-валидация — обязательный слой защиты. Фронтенд-валидация —
для UX. Допускаем дробные значения (6.5%) с одним десятичным знаком.

**Alternatives considered**:
- Slider вместо TextField — отклонён: менее точный ввод для конкретных значений
  (6%, 13%, 15%)
- Dropdown с предустановленными ставками — отклонён: ограничивает пользователя,
  не все ставки можно предусмотреть

## R4: Получение taxRate в контроллере статистики

**Decision**: Контроллер `getStatistics` уже имеет `req.user.userId` из JWT.
Добавить запрос `prisma.user.findUnique({ where: { id: userId }, select: { taxRate: true } })`
в существующий `Promise.all`.

**Rationale**: Один лёгкий запрос по primary key. Параллельное выполнение
с остальными запросами не добавляет latency.

**Alternatives considered**:
- Хранить taxRate в JWT — отклонено: JWT не обновляется при изменении ставки,
  потребует перелогина
- Передавать taxRate как query-параметр — отклонено: нарушает принцип серверного
  расчёта, клиент может передать некорректное значение
