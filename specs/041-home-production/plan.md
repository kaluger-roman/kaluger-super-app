# План восстановления

1. Проверить SSH, Docker, свободное место, сеть и сохранённую конфигурацию.
2. Зафиксировать последний целый бэкап, его SHA-256 и время восстановления.
3. Устранить ссылку Tailscale exit node на потерянный VPS; включить Serve после
   подтверждения владельца. Не изменять публичный DNS.
4. Создать отдельный каталог `super-app-production`, приватные runtime env-файлы,
   production-образы backend/web и Docker PostgreSQL 16 без опубликованного порта.
5. Сохранить отдельный recovery-экземпляр дампа вне каталога автоматической retention.
   Создать отдельную роль без superuser и восстановить БД одной транзакцией.
6. Сверить агрегаты, выполнить Prisma migrate deploy, проверить deploy env и запустить
   backend/web. Выставить доверенный адрес локального HTTPS-прокси в nginx.
7. Проверить только чтение: health, login page, защищённые API и WebSocket handshake;
   создать и проверить новый операционный бэкап. Проверить перезапуск контейнеров.
8. Обновить эксплуатационную документацию и changelog, проверить diff, отправить
   task-ветку в draft PR и дождаться CI. Не переводить ready, не merge/deploy публично.

## Границы

Прежние dev/QA-каталоги и базы не удаляются. Старый VPS не используется. Настройка
TURN, внешнего IP/роутера, нового независимого offsite-хранилища и публичного CD
отделена от текущего локального восстановления. Новая БД не используется для тестов.
