# Feature Specification: Фильтрация уроков по дате оплаты

**Feature Branch**: `024-lesson-payment-filter`
**Created**: 2026-03-24
**Status**: Draft
**Input**: User description: "добавить функционал поиска/фильтрации уроков по дате оплаты"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Фильтрация уроков по диапазону дат оплаты (Priority: P1)

Репетитор хочет увидеть все уроки, оплаченные за определённый период (например, за последний месяц или за конкретную неделю), чтобы контролировать поступление оплат и вести финансовый учёт.

**Why this priority**: Это основная потребность — возможность отфильтровать уроки по конкретному временному диапазону оплаты. Без этого невозможен финансовый контроль по периодам.

**Independent Test**: Можно протестировать, задав диапазон дат оплаты и проверив, что в результатах отображаются только уроки, оплаченные в указанный период.

**Acceptance Scenarios**:

1. **Given** репетитор находится на странице уроков в режиме «Постранично» или «Еженедельно», **When** он задаёт диапазон дат оплаты (начало и конец), **Then** в списке отображаются только уроки, у которых дата оплаты попадает в указанный диапазон.
2. **Given** репетитор задал диапазон дат оплаты, **When** ни один урок не был оплачен в этот период, **Then** отображается пустой список с информационным сообщением.
3. **Given** репетитор задал диапазон дат оплаты, **When** он сбрасывает фильтр, **Then** отображается полный список уроков без фильтрации по дате оплаты.
4. **Given** репетитор задал только начальную дату оплаты (без конечной), **When** применяется фильтр, **Then** отображаются все уроки, оплаченные начиная с указанной даты.
5. **Given** репетитор задал только конечную дату оплаты (без начальной), **When** применяется фильтр, **Then** отображаются все уроки, оплаченные до указанной даты включительно.

---

### User Story 2 - Комбинирование фильтра по дате оплаты с существующими фильтрами (Priority: P2)

Репетитор хочет совмещать фильтр по дате оплаты с другими существующими фильтрами (например, «Только неоплаченные», фильтр по ученику, по статусу), чтобы гибко находить нужные уроки.

**Why this priority**: Фильтры должны работать совместно, чтобы репетитор мог точечно находить информацию. Без этого фильтр по дате оплаты будет менее полезен.

**Independent Test**: Можно протестировать, задав диапазон дат оплаты одновременно с другим фильтром и проверив, что результаты удовлетворяют обоим условиям.

**Acceptance Scenarios**:

1. **Given** репетитор задал диапазон дат оплаты, **When** он также включает фильтр «Только неоплаченные», **Then** фильтр по дате оплаты автоматически отключается (так как неоплаченные уроки не имеют даты оплаты), и применяется только фильтр «Только неоплаченные».
2. **Given** репетитор задал диапазон дат оплаты и выбрал конкретного ученика, **When** применяются оба фильтра, **Then** отображаются только уроки этого ученика, оплаченные в указанный период.

---

### User Story 3 - Быстрый выбор предустановленных периодов оплаты (Priority: P3)

Репетитор хочет быстро выбрать типовой период (текущий месяц, прошлый месяц, текущая неделя) для просмотра оплаченных уроков, чтобы не вводить даты вручную каждый раз.

**Why this priority**: Удобство использования — типовые периоды покрывают большинство сценариев финансового контроля и экономят время.

**Independent Test**: Можно протестировать, нажав на предустановленный период и проверив, что поля дат заполнились корректными значениями и фильтр применился.

**Acceptance Scenarios**:

1. **Given** репетитор находится на странице уроков с фильтрами, **When** он выбирает предустановленный период «Текущий месяц», **Then** диапазон дат оплаты автоматически заполняется первым и последним днём текущего месяца и фильтр применяется.
2. **Given** репетитор выбрал предустановленный период, **When** он затем вручную изменяет одну из дат, **Then** предустановленный период сбрасывается, и используются вручную введённые даты.

---

### Edge Cases

- Что происходит, если начальная дата больше конечной? Система показывает ошибку валидации и не применяет фильтр.
- Как обрабатываются уроки с отсутствующей датой оплаты (неоплаченные)? Они исключаются из результатов при активном фильтре по дате оплаты.
- Что происходит при переключении режима отображения (Расписание/Еженедельно/Постранично)? Фильтр по дате оплаты доступен только в режимах «Постранично» и «Еженедельно», как и другие фильтры.
- Что происходит с пагинацией при применении фильтра? Пагинация сбрасывается на первую страницу при изменении фильтра.
- Что происходит, если репетитор включает «Только неоплаченные» при активном фильтре по дате оплаты? Фильтр по дате оплаты автоматически сбрасывается, поля дат очищаются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставить возможность фильтрации уроков по диапазону дат оплаты (начальная и конечная даты).
- **FR-002**: Система ДОЛЖНА поддерживать частичный диапазон — только начальная дата (все уроки, оплаченные с указанной даты) или только конечная дата (все уроки, оплаченные до указанной даты).
- **FR-003**: Система ДОЛЖНА исключать из результатов неоплаченные уроки (где дата оплаты отсутствует) при активном фильтре по дате оплаты.
- **FR-004**: Система ДОЛЖНА автоматически отключать фильтр по дате оплаты при включении фильтра «Только неоплаченные», так как эти фильтры взаимоисключающие.
- **FR-005**: Система ДОЛЖНА валидировать, что начальная дата не позже конечной даты, и показывать сообщение об ошибке при нарушении.
- **FR-006**: Система ДОЛЖНА сбрасывать пагинацию на первую страницу при изменении фильтра по дате оплаты.
- **FR-007**: Система ДОЛЖНА предоставить предустановленные периоды для быстрого выбора: «Текущий месяц», «Прошлый месяц», «Текущая неделя».
- **FR-008**: Система ДОЛЖНА позволять пользователю сбросить фильтр по дате оплаты для возврата к нефильтрованному списку.
- **FR-009**: Фильтр по дате оплаты ДОЛЖЕН комбинироваться с другими существующими фильтрами (по ученику, по статусу, без домашнего задания).

### Key Entities

- **Lesson (Урок)**: Основная сущность. Ключевые атрибуты для фильтрации: дата оплаты, статус оплаты, цена. Связан с учеником и репетитором.
- **Payment Date Filter (Фильтр по дате оплаты)**: Пользовательский ввод, состоящий из начальной даты, конечной даты и опционально выбранного предустановленного периода.

## Assumptions

- Фильтр по дате оплаты размещается рядом с существующими фильтрами (переключатели «Только неоплаченные» и «Только без Д/З») на странице уроков.
- Предустановленные периоды реализуются как набор кнопок-чипов рядом с полями выбора дат.
- Поля дат используют стандартные компоненты выбора даты, уже используемые в приложении.
- Фильтр по дате оплаты видим только в режимах «Постранично» и «Еженедельно», аналогично другим фильтрам.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Репетитор может отфильтровать уроки по диапазону дат оплаты и получить корректные результаты менее чем за 2 секунды.
- **SC-002**: Выбор предустановленного периода заполняет даты и применяет фильтр за одно действие (один клик).
- **SC-003**: Все комбинации фильтров (дата оплаты + другие фильтры) возвращают корректные, непротиворечивые результаты.
- **SC-004**: Фильтр интуитивно понятен — репетитор может найти оплаты за период без обучения или подсказок.
