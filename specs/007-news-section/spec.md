# Feature Specification: Раздел «Новости»

**Feature Branch**: `007-news-section`
**Created**: 2026-02-22
**Status**: Draft
**Input**: User description: "нужна новая фича - раздел новости, туда будем постить имеющую значение для пользователя информацию из ченжлога проекта, на русском языке, оно должно добавляться при обновлении ченжлога и наличии в ченжесах видимых для юзера изменений"

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Просмотр новостей (Priority: P1)

Пользователь заходит в раздел «Новости» и видит список обновлений приложения, описанных понятным языком на русском. Каждая новость содержит заголовок, дату и описание изменений. Новости отсортированы от новых к старым.

**Why this priority**: Основная ценность фичи — пользователь должен иметь возможность узнать, что изменилось в приложении. Без этого сценария фича не имеет смысла.

**Independent Test**: Можно полностью протестировать, создав тестовые записи новостей и проверив их отображение в разделе «Новости».

**Acceptance Scenarios**:

1. **Given** в системе есть опубликованные новости, **When** пользователь открывает раздел «Новости», **Then** отображается список новостей, отсортированных от новых к старым
2. **Given** в системе нет опубликованных новостей, **When** пользователь открывает раздел «Новости», **Then** отображается сообщение «Пока нет новостей»
3. **Given** в системе есть новости, **When** пользователь просматривает список, **Then** каждая новость содержит заголовок, дату публикации и описание изменений на русском языке

---

### User Story 2 — Индикатор непрочитанных новостей (Priority: P2)

Пользователь видит визуальный индикатор (бейдж) на пункте меню «Новости» в сайдбаре, если появились новые новости, которые он ещё не просматривал. После открытия раздела «Новости» индикатор исчезает.

**Why this priority**: Без индикатора пользователь может не узнать о новых обновлениях. Индикатор привлекает внимание и повышает вовлечённость.

**Independent Test**: Можно протестировать, создав новую новость и проверив наличие бейджа, а затем открыв раздел и убедившись, что бейдж исчез.

**Acceptance Scenarios**:

1. **Given** появилась новая новость после последнего посещения пользователем раздела «Новости», **When** пользователь видит сайдбар, **Then** на пункте «Новости» отображается индикатор (бейдж)
2. **Given** на пункте «Новости» есть бейдж, **When** пользователь открывает раздел «Новости», **Then** бейдж исчезает
3. **Given** пользователь уже просмотрел все новости, **When** новых новостей не появилось, **Then** бейдж не отображается

---

### User Story 3 — Создание новости из changelog (Priority: P1)

При обновлении changelog проекта, если в изменениях есть пользовательски значимые обновления (новые функции, исправления багов, изменения интерфейса), создаётся новая запись новости. Текст новости пишется на русском языке, понятным для пользователя образом, без технических деталей.

**Why this priority**: Это механизм наполнения раздела «Новости» контентом. Без него раздел будет пустым.

**Independent Test**: Можно протестировать, вызвав процесс генерации новости из changelog и убедившись, что запись создана в системе.

**Acceptance Scenarios**:

1. **Given** changelog обновлён и содержит пользовательски значимые изменения (Added, Changed, Fixed, Removed), **When** запускается процесс генерации новостей, **Then** создаётся новая запись новости с описанием на русском языке
2. **Given** changelog обновлён, но все изменения технические (рефакторинг, CI/CD, тесты), **When** запускается процесс генерации новостей, **Then** новая запись не создаётся
3. **Given** changelog не изменился с последнего запуска, **When** запускается процесс генерации новостей, **Then** дублирующая запись не создаётся

---

### Edge Cases

- Что происходит, когда пользователь открывает раздел «Новости» при отсутствии подключения к серверу? — Отображается последнее кешированное состояние или сообщение об ошибке
- Что происходит при большом количестве новостей? — Используется постраничная загрузка (пагинация)
- Что если changelog содержит смешанные изменения (и пользовательские, и технические)? — В новость попадают только пользовательски значимые пункты
- Что если текст новости получается слишком длинным? — Отображается сокращённая версия с возможностью раскрыть полный текст

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять раздел «Новости», доступный из бокового меню (сайдбара) для всех авторизованных пользователей
- **FR-002**: Система MUST отображать список новостей, отсортированных по дате публикации от новых к старым
- **FR-003**: Каждая новость MUST содержать: заголовок, дату публикации, описание изменений
- **FR-004**: Описание новости MUST быть написано на русском языке, понятным для пользователя образом, без технических терминов
- **FR-005**: Система MUST поддерживать постраничную загрузку новостей при большом количестве записей
- **FR-006**: Система MUST отображать индикатор (бейдж) на пункте «Новости» в сайдбаре, если есть новости, которые пользователь ещё не просмотрел
- **FR-007**: Система MUST убирать индикатор непрочитанных новостей после посещения пользователем раздела «Новости»
- **FR-008**: Система MUST предоставлять механизм создания новостей из changelog, фильтруя только пользовательски значимые изменения (Added, Changed, Fixed, Removed, Security)
- **FR-009**: Система MUST НЕ создавать дублирующие новости для уже обработанных записей changelog
- **FR-010**: Система MUST отображать информативное сообщение, когда список новостей пуст

### Key Entities

- **Новость (NewsItem)**: Информационная запись об обновлении приложения. Содержит: заголовок, описание, дату публикации, ссылку на версию changelog
- **Прочтение новостей (NewsReadStatus)**: Запись о том, когда пользователь последний раз посещал раздел новостей. Связана с пользователем

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователи могут открыть раздел «Новости» и увидеть актуальные обновления приложения за менее чем 2 секунды
- **SC-002**: 100% пользовательски значимых изменений из changelog попадают в раздел новостей
- **SC-003**: 0% технических изменений (рефакторинг, CI/CD, тесты) попадают в раздел новостей
- **SC-004**: Индикатор непрочитанных новостей исчезает при посещении раздела в 100% случаев
- **SC-005**: Новости отображаются на русском языке без технического жаргона

## Assumptions

- Процесс генерации новостей из changelog запускается вручную разработчиком (командой/скриптом) в рамках процесса релиза, а не автоматически при каждом коммите
- Все пользователи системы (репетиторы) видят одинаковые новости — нет разделения по ролям
- Текст новости формируется разработчиком или генерируется из changelog с последующей редакцией — ответственность за качество текста на русском языке лежит на процессе создания
- Пагинация новостей начинается при количестве записей более 20
- Раздел «Новости» доступен только авторизованным пользователям
